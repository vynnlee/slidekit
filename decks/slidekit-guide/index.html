slidekit

HTML로 만드는 슬라이드 도구

**slidekit**을 소개하는 발표이다. 이 덱 자체가 slidekit으로 만들어졌다. 각 장은 시작하기, 발표, 만들기, AI와 내보내기 순서로 진행한다.

시작하기

첫 장은 앱을 여는 방법과 편집기 구성이다. - 실행 - 새 덱 - 편집기와 도구 - 버전 기록

명령 하나로 시작한다

bun run slidekit앱이 127.0.0.1:3200에서 열리고 덱 목록이 나온다
slidekit new <이름>새 덱을 만든다. 덱 목록에서도 만들 수 있다
편집기레이어, 캔버스, 속성 패널, 노트를 한 화면에서 쓴다

클릭은 최상위 요소, 더블클릭은 한 단계 안쪽, Cmd+클릭은 가장 안쪽을 고른다. 입력이 1.5초 멈추면 자동 저장하고 Cmd+S로도 저장한다. 저장이 실패하면 알림이 뜨고 10초마다, 네트워크가 돌아오면 다시 시도하며 Retry 단추도 있다.

앱 실행 한 줄이면 덱 목록이 열린다. **편집은 한 화면**에서 끝나고, 저장은 자동이다. 시연: 명령을 실행해 새 덱을 만들고 편집기에서 글자를 더블클릭해 고친다. 약 1분이다.

편집기의 도구를 한곳에서 쓴다

Cmd+K명령 팔레트. 처음에는 Present, Add slide, Find, Add comment, Keyboard shortcuts를 보여 준다
Cmd+F찾기와 바꾸기. 슬라이드 글자를 한꺼번에 고친다
Cmd+G선택을 그룹으로 묶고 Shift+Cmd+G로 푼다. Cmd+Alt+C와 V는 스타일 복사와 붙여넣기

우클릭 메뉴(요소, 그룹, 빈 곳, Layers, 필름스트립 타일), 글자 스타일 프리셋, 이미지 붙여넣기와 끌어 놓기도 있다. 전체 목록은 Keyboard shortcuts(Cmd+/)에서 본다.

모든 도구는 **키보드로 닿는다**. 그룹은 요소를 한 덩어리로 옮기고 자식의 스타일은 그대로 둔다. 그라디언트는 색상 선택기의 Gradient 탭에서 고른다. 시연: Cmd+K로 팔레트를 열어 슬라이드로 이동하고 Cmd+F로 단어 하나를 바꿔 본다. 약 1분이다.

색은 색상 선택기에서 고른다

GradientFill과 Background에서 스톱 2~4개의 선형 그라디언트를 만든다
Deck colors덱 토큰을 고르면 var()로 연결되어 토큰을 바꿀 때 함께 바뀐다
Recent최근 색과 글자색 대비 칩을 함께 보여 준다

PDF에서도 그라디언트는 벡터로 남는다.

**토큰으로 연결한 색**은 테마를 바꿀 때 같이 바뀐다. 대비 칩은 글자와 배경의 WCAG 대비를 알려 준다. 색상 선택기에서 Gradient 탭을 열어 스톱을 끌어 보인다. 토큰 색을 고르면 테마를 바꿀 때 같이 바뀐다고 말한다.

저장하면 버전이 남는다

버전 기록편집기의 Version history가 저장 직전의 내용을 스냅샷으로 보관한다
비교와 미리보기고르기 전에 지금 내용과 비교하고 새 탭에서 미리 볼 수 있다
복원되돌리면 복원 직전의 내용도 하나 남고 Undo로 취소한다

편집기 밖에서 파일을 고쳐도 바뀌기 직전의 내용이 남는다.

**실수해도 되돌릴 수 있다**. 덱마다 30MB까지 보관하고 오래된 것부터 지운다. 시연: 글자를 하나 지우고 저장한 뒤 Version history에서 복원한다. 실수해도 되돌릴 수 있다는 점이 요점이다.

발표

두 번째 장은 발표 중 사용하는 조작이다. 이동 규칙, 발표자 화면, 휴대폰 리모컨을 다룬다.

이동은 방향키 하나로 한다

← →앞뒤로 이동한다. 클릭, 스페이스, 스와이프로는 넘어가지 않는다.
F OF는 전체화면, O는 전체 보기이다.
B W화면을 검게 또는 희게 가린다.

편집기에서는 Cmd+Enter가 현재 슬라이드부터, Shift+Cmd+Enter가 처음부터 발표한다. 발표 중 숫자를 입력하고 Enter를 누르면 그 번호의 장으로 간다. 발표자 화면은 현재와 다음 슬라이드, 노트, 타이머를 보여 주고 외장 모니터에 발표 화면을 띄운다.

이동 수단을 방향키로 제한한 이유는 **발표 중 오작동을 막기 위해서**이다. 발표자 화면의 항목은 필요한 것만 켜 둔다. 외장 모니터는 Chrome 계열 브라우저에서 쓴다. 청중에게 방향키만 쓴다고 먼저 말한다. 숫자와 Enter로 장 이동, B와 W로 화면 가리기를 보여 준다.

노트와 발표자 화면

노트슬라이드마다 aside에 마크다운으로 쓴다. 청중 화면에는 나오지 않는다
발표자 화면현재와 다음 슬라이드, 노트, 타이머, 장 위치를 필요한 것만 켜 둔다
리허설T로 타이머를 시작하면 슬라이드별 체류 시간이 쌓이고 목표 시간과 비교한다

발표 창을 닫았다가 다시 열어도 위치와 가리기 상태가 이어진다.

노트는 **발표자만** 보는 글이다. 읽을 말, 시간 배분, 예상 질문을 적는다. 리허설 요약은 가장 오래 머문 세 장을 보여 준다. 발표자 화면을 열어 노트가 청중 화면에 나오지 않음을 보인다. T로 타이머를 켠다.

휴대폰을 리모컨으로 쓴다

시작발표자 화면의 리모컨 버튼이 QR 코드와 주소를 보여 준다
연결휴대폰이 코드를 한 번 쓰면 그 코드는 닫히고 세션은 두 시간 유지된다
조작넘기기, 화면 가리기, 타이머를 조종하고 현재 슬라이드의 노트를 읽는다

같은 네트워크의 휴대폰만 쓰고 공개 인터넷에는 열지 않는다.

리모컨은 **발표자 화면이 켜져 있는 동안만** 동작한다. 연결이 끊기면 발표자 화면에서 다시 시작한다. 시연: 휴대폰으로 QR을 읽어 연결하고 넘기기를 해 본다. 같은 네트워크에서만 되고 발표자 화면이 켜져 있어야 한다.

만들기

세 번째 장은 덱을 쓰는 규격이다. 종류, 레이아웃, 토큰, 테마, 설정, 단계 등장을 다룬다.

규격은 네 가지만 기억한다

종류cover, chapter, content, end. 장 표지에는 data-title이 필요하다.
화면1920x1080 고정이고 창에 맞춰 엔진이 줄이고 늘린다.
토큰색, 글꼴, 여백, 글자 크기는 --sk- 변수이고 토큰 패널에서 바꾼다.
노트와 글꼴노트는 aside에 마크다운으로 쓴다. 글꼴은 번들 때 쓰는 글자만 남겨 인라인한다.
규격 문서는 `spec/SPEC.md`이고 AI에게는 **스킬**이 같은 내용을 요약해 준다. 토큰은 `:root` 한 블록에 모으면 편집기가 원문 그대로 고친다.

모양은 레이아웃으로 고른다

two-column비교, 전과 후, 글과 그림처럼 둘을 나란히 놓는다.
big-number숫자 하나로 말한다.
quote인용과 출처를 보여 준다.
image-full이미지가 슬라이드를 채우고 글은 아래쪽에 겹친다.

본문 슬라이드에 data-layout을 달면 된다. 없으면 제목과 본문이다. 목록은 slidekit layouts로 보고, 편집기에서는 Add slide 메뉴, 필름스트립 타일 우클릭의 Layout(숫자 키 1~5), Inspector의 Layout 칩으로 고른다.

레이아웃은 슬라이드 **종류가 아니라 본문의 변형**이다. 종류 네 가지 규칙은 그대로이다. 편집기에서는 슬라이드를 추가할 때 고르고 Inspector에서 바꾼다. 다섯 레이아웃을 차례로 소개한다. 뒤의 두 장이 big-number와 two-column의 실제 예이다.

5

레이아웃 프리셋은 다섯 가지이다. 이 슬라이드가 big-number이다.

숫자 하나가 말하게 하는 레이아웃이다. 설명은 한 줄로 줄인다. 숫자 하나가 말하게 한다. 숫자 5를 말하고 다음 장으로 넘어간다.

두 열은 비교에 쓴다

파일을 직접 고칠 때

원본 HTML 한 파일을 연다. AI에게 맡기거나 직접 쓴다.

편집기를 쓸 때

캔버스에서 고르고 속성 패널로 바꾼다. 저장은 자동이다.

두 방법은 **같은 파일**을 고친다. 어느 쪽으로 시작해도 된다.

도구는 생각을 가리지 않을 때 가장 좋다.

quote 레이아웃
인용과 출처를 보여 주는 레이아웃이다. 인용은 한 문장으로 줄인다. 인용 레이아웃이다. 한 문장만 읽고 넘어간다.

image-full은 이미지가 채운다

이미지가 슬라이드를 채우고 글은 아래쪽에 겹친다. 이미지에는 항상 alt를 적는다.

토큰으로 모양을 바꾼다

--sk-accent강조 색 하나로 덱 전체의 분위기가 바뀐다
--sk-font글꼴은 번들 때 쓰는 글자만 남겨 파일에 담긴다
--sk-pad-x여백과 글자 크기도 변수이고 토큰 패널에서 고친다

토큰은 :root 한 블록에 모으면 편집기가 원문 그대로 고친다.

토큰만 바꾸면 슬라이드 본문은 건드리지 않는다. 바꾼 값에는 **Reset 점**이 생겨 기본값으로 되돌릴 수 있다. 시연: 토큰 패널에서 강조 색을 바꿔 덱 전체가 바뀌는 것을 보인다.

테마와 덱 설정

Theme토큰 패널에서 테마를 고르면 색과 글꼴 토큰이 한 번에 바뀐다
Deck settings제목, 부제, 작성자, 날짜, 언어, 공개 범위를 폼에서 고친다
저장바꾸는 즉시 저장되고 표지 글자는 건드리지 않는다

설정은 deck-meta 블록과 html lang에 기록된다.

테마는 **토큰 값의 묶음**일 뿐이라 이후에 토큰을 따로 고쳐도 된다. 공개 범위가 비밀번호이면 비밀번호는 게시할 때 묻고 덱에는 저장하지 않는다. 시연: Theme을 바꾸고 Deck settings에서 제목을 고친다. 공개 범위는 게시할 때 쓰인다.

방향키로 하나씩 나타난다

이 슬라이드는 data-step을 실제로 사용한다.

  • data-step="N"을 달면 N단계부터 보인다.
  • 효과는 data-step-effect로 rise, fade, left, scale, blur, none 중 고른다.
  • JS가 필요 없다.
방향키를 누를 때마다 항목이 하나씩 나타난다. 두 번째는 **fade**, 세 번째는 **none** 효과이다. 그 밖에 left, scale, blur가 있다. 이 장 자체가 데모이다. 방향키를 눌러 항목이 하나씩 나타나게 한다.

AI와 내보내기

마지막 장은 AI 연동과 산출물이다. 코멘트 흐름, 번들, PDF, 배포, 게시 취소를 다룬다.

AI와 함께 덱을 만든다

코멘트요소를 골라 남기면 열려 있는 Claude Code 세션이 받아 덱을 고치고 답한다
스킬저장소의 slidekit 스킬을 읽은 AI가 규격에 맞는 덱을 새로 만든다
lintslidekit lint가 규격 위반을 알려 준다

편집기에서는 C 키, 우클릭, 팔레트의 Add comment로 쓰고, 열린 코멘트가 있는 슬라이드는 필름스트립에 점이 보인다. 작성창의 Hold until I send all to Claude를 켜면 코멘트가 보류로 쌓이고, Send all to Claude가 한 번에 10개까지 묶어 보낸다. 코멘트는 파일에도 저장된다(Claude Code Channels).

AI와의 협업은 **코멘트, 스킬, lint** 세 도구로 이루어진다. 코멘트는 파일에도 남아 놓친 것을 다시 가져올 수 있다. 시연: 요소에 코멘트를 쓰고 Claude Code 세션이 고치는 과정을 보인다. 코멘트가 여럿이면 Hold로 모아 한 번에 보낸다.

내보내기는 세 가지이다

bundle엔진, 이미지, 글꼴을 담은 HTML 파일 하나
pdf슬라이드당 한 페이지, 16:9. 노트를 넣은 쪽과 한 장에 2, 3, 4, 6장씩 모은 유인물도 만든다
deploystatic.vynnlee.com, 공개 또는 비밀번호

편집기의 Export 메뉴에서도 같은 일을 한다.

산출물은 **번들, PDF, 배포** 세 가지이다. 명령은 `slidekit bundle`, `slidekit pdf`, `slidekit deploy`이고 Export 메뉴와 같은 기능을 쓴다. 세 산출물을 비교한다. 오프라인 발표에는 번들이 가장 안전하고 PDF는 백업이다.

게시를 취소한다

Export 메뉴Unpublish는 지울 주소를 보여 주고 확인을 받은 뒤에만 지운다
slidekit unpublish덱 이름만 주면 지울 목록만 보인다. 정말 지울 때만 --yes를 붙인다
남는 것로컬 덱과 dist 파일은 그대로이고 게시된 주소만 닫힌다

게시 기록은 덱 폴더의 .publish.json에 남는다.

**취소는 되돌릴 수 없다**. 다시 올리면 같은 주소로 열린다. 취소는 되돌릴 수 없다는 점을 먼저 말한다. --yes 없이 지울 목록부터 본다.

배포 전에 점검한다

slidekit lint규격 위반과 남은 예제 문구를 알려 준다
slidekit doctor실행 환경을 점검하고, 덱 이름을 주면 이미지, 대비, 노트를 점검한다. --layout은 넘침과 잘림을 잰다
비밀번호비밀번호 덱은 8자 이상이고 링크와 따로 전달한다

Export 메뉴의 Publish도 올리기 전에 같은 점검을 보여 준다. 편집기도 같은 기준의 넘침을 캔버스 외곽선, Layers의 경고 삼각형, 필름스트립 표시, View의 Safe area로 보여 준다.

배포는 **공개 사이트에 올리는 일**이다. lint 경고를 모두 읽고 올린다. 비밀번호는 덱 안에 넣지 않는다. doctor의 경고 항목을 하나씩 짚는다. 외부 글꼴 경고가 나오면 번들이 필요하다.

발표 전에 다섯 가지를 확인한다

  • slidekit doctor <덱> --layout가 경고 없이 끝난다.
  • slidekit bundle <덱>으로 HTML 한 파일을 만든다. 외부 글꼴이 있으면 꼭 한다.
  • slidekit pdf <덱> --notes로 백업 PDF를 만든다.
  • 번들 HTML을 네트워크를 끊고 한 번 끝까지 넘겨 본다.
  • 휴대폰 리모컨과 프로젝터는 docs/DEVICE-CHECKLIST.md로 실기기에서 확인한다.
