slidekit

HTML로 만드는 슬라이드 도구

**slidekit**을 소개하는 발표이다. 이 덱 자체가 slidekit으로 만들어졌다. 각 장은 시작하기, 발표, 만들기, AI와 내보내기 순서로 진행한다.

시작하기

첫 장은 앱을 여는 방법과 편집기 구성이다. - 실행 - 새 덱 - 편집기

명령 하나로 시작한다

bun run slidekit앱이 127.0.0.1:3200에서 열리고 덱 목록이 나온다
slidekit new <이름>새 덱을 만든다. 덱 목록에서도 만들 수 있다
편집기레이어, 캔버스, 속성 패널, 노트를 한 화면에서 쓴다

더블클릭하면 글자를 고친다. 입력이 1.5초 멈추면 자동 저장하고 Cmd+S로도 저장한다.

앱 실행 한 줄이면 덱 목록이 열린다. **편집은 한 화면**에서 끝나고, 저장은 자동이다.

발표

두 번째 장은 발표 중 사용하는 조작이다. 이동 규칙과 발표자 화면을 다룬다.

이동은 방향키 하나로 한다

← →앞뒤로 이동한다. 클릭, 스페이스, 스와이프로는 넘어가지 않는다.
F OF는 전체화면, O는 전체 보기이다.
B W화면을 검게 또는 희게 가린다.

숫자를 입력하고 Enter를 누르면 그 번호의 장으로 간다. 발표자 화면은 현재와 다음 슬라이드, 노트, 타이머를 보여 주고 외장 모니터에 발표 화면을 띄운다.

이동 수단을 방향키로 제한한 이유는 **발표 중 오작동을 막기 위해서**이다. 발표자 화면의 항목은 필요한 것만 켜 둔다. 외장 모니터는 Chrome 계열 브라우저에서 쓴다.

노트와 발표자 화면

노트슬라이드마다 aside에 마크다운으로 쓴다. 청중 화면에는 나오지 않는다
발표자 화면현재와 다음 슬라이드, 노트, 타이머, 장 위치를 필요한 것만 켜 둔다
리허설T로 타이머를 시작하면 슬라이드별 체류 시간이 쌓이고 목표 시간과 비교한다

발표 창을 닫았다가 다시 열어도 위치와 가리기 상태가 이어진다.

노트는 **발표자만** 보는 글이다. 읽을 말, 시간 배분, 예상 질문을 적는다. 리허설 요약은 가장 오래 머문 세 장을 보여 준다.

만들기

세 번째 장은 덱을 쓰는 규격이다. 종류, 토큰, 노트, 글꼴, 단계 등장을 다룬다.

규격은 네 가지만 기억한다

종류cover, chapter, content, end. 장 표지에는 data-title이 필요하다.
화면1920x1080 고정이고 창에 맞춰 엔진이 줄이고 늘린다.
토큰색, 글꼴, 여백, 글자 크기는 --sk- 변수이고 토큰 패널에서 바꾼다.
노트와 글꼴노트는 aside에 마크다운으로 쓴다. 글꼴은 번들 때 쓰는 글자만 남겨 인라인한다.
규격 문서는 `spec/SPEC.md`이고 AI에게는 **스킬**이 같은 내용을 요약해 준다. 토큰은 `:root` 한 블록에 모으면 편집기가 원문 그대로 고친다.

모양은 레이아웃으로 고른다

two-column비교, 전과 후, 글과 그림처럼 둘을 나란히 놓는다.
big-number숫자 하나로 말한다.
quote인용과 출처를 보여 준다.
image-full이미지가 슬라이드를 채우고 글은 아래쪽에 겹친다.

본문 슬라이드에 data-layout을 달면 된다. 없으면 제목과 본문이다. 목록은 slidekit layouts로 본다.

레이아웃은 슬라이드 **종류가 아니라 본문의 변형**이다. 종류 네 가지 규칙은 그대로이다. 편집기에서는 슬라이드를 추가할 때 고르고 Inspector에서 바꾼다.

5

레이아웃 프리셋은 다섯 가지이다. 이 슬라이드가 big-number이다.

숫자 하나가 말하게 하는 레이아웃이다. 설명은 한 줄로 줄인다.

두 열은 비교에 쓴다

파일을 직접 고칠 때

원본 HTML 한 파일을 연다. AI에게 맡기거나 직접 쓴다.

편집기를 쓸 때

캔버스에서 고르고 속성 패널로 바꾼다. 저장은 자동이다.

두 방법은 **같은 파일**을 고친다. 어느 쪽으로 시작해도 된다.

토큰으로 모양을 바꾼다

--sk-accent강조 색 하나로 덱 전체의 분위기가 바뀐다
--sk-font글꼴은 번들 때 쓰는 글자만 남겨 파일에 담긴다
--sk-pad-x여백과 글자 크기도 변수이고 토큰 패널에서 고친다

토큰은 :root 한 블록에 모으면 편집기가 원문 그대로 고친다.

토큰만 바꾸면 슬라이드 본문은 건드리지 않는다. 바꾼 값에는 **Reset 점**이 생겨 기본값으로 되돌릴 수 있다.

방향키로 하나씩 나타난다

이 슬라이드는 data-step을 실제로 사용한다.

  • data-step="N"을 달면 N단계부터 보인다.
  • 효과는 data-step-effect로 rise, fade, none 중 고른다.
  • JS가 필요 없다.
방향키를 누를 때마다 항목이 하나씩 나타난다. 두 번째는 **fade**, 세 번째는 **none** 효과이다.

AI와 내보내기

마지막 장은 AI 연동과 산출물이다. 코멘트 흐름, 번들, PDF, 배포를 다룬다.

AI와 함께 덱을 만든다

코멘트요소를 골라 남기면 열려 있는 Claude Code 세션이 받아 덱을 고치고 답한다
스킬저장소의 slidekit 스킬을 읽은 AI가 규격에 맞는 덱을 새로 만든다
lintslidekit lint가 규격 위반을 알려 준다

코멘트는 파일에도 저장된다(Claude Code Channels).

AI와의 협업은 **코멘트, 스킬, lint** 세 도구로 이루어진다. 코멘트는 파일에도 남아 놓친 것을 다시 가져올 수 있다.

내보내기는 세 가지이다

bundle엔진, 이미지, 글꼴을 담은 HTML 파일 하나
pdf슬라이드당 한 페이지, 16:9
deploystatic.vynnlee.com, 공개 또는 비밀번호

편집기의 Export 메뉴에서도 같은 일을 한다.

산출물은 **번들, PDF, 배포** 세 가지이다. 명령은 `slidekit bundle`, `slidekit pdf`, `slidekit deploy`이고 Export 메뉴와 같은 기능을 쓴다.

배포 전에 점검한다

slidekit lint규격 위반과 남은 예제 문구를 알려 준다
slidekit doctorChrome, 토큰, 포트 같은 실행 환경을 한 화면에 점검한다
비밀번호비밀번호 덱은 8자 이상이고 링크와 따로 전달한다

Export 메뉴의 Publish도 올리기 전에 같은 점검을 보여 준다.

배포는 **공개 사이트에 올리는 일**이다. lint 경고를 모두 읽고 올린다. 비밀번호는 덱 안에 넣지 않는다.
