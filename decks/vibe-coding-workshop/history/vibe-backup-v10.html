코딩 에이전트 생태계

모든 코딩 에이전트의 중심에는 대형 언어 모델이 있다.

대형 언어 모델(LLM)은 방대한 텍스트와 코드로 학습하여, 입력된 내용에 이어질 내용을 생성하는 AI 모델이다. 모델마다 성능, 속도, 비용이 다르다.

코딩 에이전트는 모델에 작업 도구를 연결한 프로그램이다.

모델판단과 코드 생성
코딩 에이전트파일 읽기와 쓰기, 명령 실행, 브라우저 조작
내 컴퓨터프로젝트 폴더

같은 모델이라도 어떤 에이전트에서 사용하는지에 따라 할 수 있는 작업과 결과의 품질이 달라진다.

코딩 에이전트는 실행되는 위치에 따라 두 가지로 나뉜다.

로컬 에이전트

로컬 에이전트클라우드 에이전트

이 수업은 로컬 에이전트인 Antigravity를 사용한다. 폴더, Git, 배포의 흐름을 직접 다루기 때문이다.

Antigravity는 Google이 만든 에이전트 중심 개발 도구다.

Antigravity 2.0여러 에이전트에게 작업을 맡기고 진행 상황을 관리하는 데스크톱 앱. 이 수업에서 사용한다.

요금제요금제에 따라 사용 한도가 다르며, Google AI Pro를 구독하면 한도가 늘어난다.

AI 도구의 사용량과 처리 한계는 모두 토큰으로 계산된다.

사용 한도요금제마다 일정 시간 동안 쓸 수 있는 토큰의 양이 정해져 있다.
요금API로 모델을 쓰면 사용한 토큰 수에 따라 비용을 낸다.
컨텍스트 윈도우모델이 한 번에 처리할 수 있는 양도 토큰 수로 정해진다.

따라서 에이전트에게 일을 맡기려면 토큰이 무엇이고, 무엇이 토큰을 소비하는지 알아야 한다.

토큰은 모델이 텍스트를 처리하는 단위다.

모델은 문장을 글자나 단어가 아닌 토큰 단위로 나누어 읽고, 답변도 토큰을 하나씩 이어 붙여 만든다. 토큰 하나는 대체로 단어 하나이거나 그보다 작은 조각이며, 같은 내용이라도 한국어는 영어보다 많은 토큰으로 나뉘는 경우가 많다.

질문 (입력)
응답 (출력)

사용량은 입력 토큰과 출력 토큰을 합해 계산된다.

입력 토큰요청, 첨부 파일, 에이전트가 읽은 파일, 이전 대화 내용
모델
출력 토큰답변, 에이전트가 작성한 코드

모델은 이전 대화를 따로 저장하지 않기 때문에, 요청할 때마다 대화 전체를 다시 입력으로 받는다. 대화가 길어질수록 요청 한 번에 드는 토큰도 늘어난다.

에이전트는 작업 중에 파일을 읽고 여러 단계를 반복하므로, 질문 하나에 답하는 챗봇보다 훨씬 많은 토큰을 사용한다. 사용 한도에 도달하면 일정 시간 동안 사용이 제한된다.

컨텍스트 윈도우는 모델이 한 번에 처리할 수 있는 토큰의 최대량이다.

지침
읽은 파일
대화 내용
남은 공간

지침, 읽은 파일, 대화 내용이 모두 이 안에 들어간다. 최신 모델의 컨텍스트 윈도우는 수십만에서 100만 토큰 수준이다.

대화가 길어져 한계에 가까워지면 앞부분이 요약되거나 제외되어, 처음에 전달한 내용이 반영되지 않을 수 있다. 새 대화를 시작하면 컨텍스트 윈도우는 비워진 상태에서 다시 시작한다.

모델은 사실이 아닌 내용을 사실처럼 말할 수 있다.

이를 환각(hallucination)이라고 한다. 존재하지 않는 기능을 사용하거나, 작업이 끝나지 않았는데 완료되었다고 보고하는 경우가 있다.

따라서 결과는 브라우저에서 직접 확인한 뒤에 완료로 판단한다.

모델이 아는 정보는 학습 시점까지로 한정된다.

모델은 학습 데이터를 수집한 시점 이후의 정보를 알지 못한다. 이 시점을 지식 기준일(knowledge cutoff)이라고 한다.

최신 서비스나 새 버전의 사용법이 필요하면 에이전트에게 웹 검색을 요청하거나, 공식 문서의 주소를 함께 전달한다.

폴더와 파일

에이전트가 다루는 대상은 내 컴퓨터의 폴더와 파일이다.

web-practice/
├── index.html
├── style.css
├── script.js
├── images/
│   └── profile.jpg
├── README.md
└── AGENTS.md

웹사이트 하나는 폴더 하나로 이루어진다.

에이전트는 이 폴더 안에 파일을 만들고, 내용을 수정하고, 필요 없는 파일을 지운다.

파일의 종류는 확장자로 구분한다.

.html페이지의 구조와 내용
.css색, 글꼴, 배치 등 화면의 모양
.js클릭이나 스크롤에 반응하는 동작
.md마크다운 문서
.json설정과 데이터
.png .jpg .svg이미지

코드 파일은 모두 텍스트 파일이다.

<!-- index.html -->
<h1>김민지</h1>
<p>시각디자인과 3학년</p>
<img src="images/profile.jpg">
<button>작업 보기</button>

이미지와 영상을 제외한 대부분의 파일은 텍스트 편집기로 열어 내용을 볼 수 있다.

에이전트가 하는 일은 이 텍스트를 작성하고 고치는 것이다.

경로는 파일의 위치를 나타내는 주소다.

절대 경로/Users/minji/Desktop/web-practice/images/profile.jpg
컴퓨터 전체를 기준으로 한 위치
상대 경로images/profile.jpg
현재 폴더를 기준으로 한 위치

폴더와 파일 이름은 영문 소문자로 짓고, 공백 대신 하이픈(-)을 사용한다. 한글과 공백이 들어간 이름은 오류의 원인이 된다.

에이전트는 지정한 폴더 안에서 작업한다.

Antigravity에서 작업을 시작할 때 프로젝트 폴더를 지정한다. 이 폴더를 워크스페이스라고 한다.

프로젝트마다 폴더를 따로 만들면 작업 내용이 섞이지 않고, 에이전트가 관련 없는 파일을 건드리지 않는다.

점(.)으로 시작하는 파일과 폴더는 기본적으로 숨겨져 있다.

.gitGit의 변경 이력이 저장되는 폴더
.gitignoreGit이 기록하지 않을 파일의 목록
.envAPI 키처럼 공개하면 안 되는 값을 저장하는 파일

macOS의 Finder에서 Command + Shift + . 을 누르면 숨김 파일이 표시된다.

브라우저는 HTML, CSS, JS 파일을 읽어 화면을 그린다.

index.html
style.css
script.js

브라우저
화면

파일을 수정한 뒤에는 브라우저를 새로고침해야 변경 내용이 화면에 반영된다.

localhost는 내 컴퓨터에서 실행 중인 임시 서버의 주소다.

http://localhost:3000localhost 뒤의 숫자는 포트 번호로, 서버마다 다르다.

에이전트는 결과를 확인하기 위해 내 컴퓨터에서 서버를 실행한다. 이 주소는 내 컴퓨터에서만 열리며, 다른 사람에게 보여 주려면 배포가 필요하다.

새 대화를 시작한 에이전트도 이 파일을 읽으면 프로젝트의 현재 상태를 파악할 수 있다.

바이브 코딩

바이브 코딩은 원하는 결과를 말로 설명하고, 코드 작성은 AI에게 맡기는 방식이다.

2025년 2월 AI 연구자 Andrej Karpathy가 처음 사용한 용어다.

사용자는 코드를 직접 읽거나 쓰지 않고, 결과물을 확인하며 수정할 내용을 전달한다.

에이전틱 코딩은 AI 에이전트가 계획, 실행, 확인을 스스로 수행하는 방식이다.

에이전트는 요청 하나를 받아 필요한 파일을 찾고, 코드를 작성하고, 명령을 실행하고, 결과를 확인하는 과정을 여러 단계에 걸쳐 진행한다.

사용자는 방향을 정하고 결과를 판단한다.

챗봇은 답을 알려 주고, 에이전트는 작업을 직접 수행한다.

챗봇

  • 코드를 답변으로 보여 준다.
  • 사용자가 코드를 복사해 파일에 붙여 넣는다.
  • 사용자가 실행하고, 오류를 다시 전달한다.

에이전트

  • 파일을 직접 만들고 수정한다.
  • 필요한 명령을 직접 실행한다.
  • 결과를 확인하고 오류를 직접 고친다.

에이전트는 도구를 사용해 실제 작업을 수행한다.

파일 읽기프로젝트의 파일 내용을 확인한다.
파일 쓰기파일을 만들고 내용을 수정한다.
명령 실행터미널에서 서버 실행, 설치 등을 처리한다.
브라우저 조작페이지를 열고 클릭하며 결과를 확인한다.
웹 검색최신 정보와 공식 문서를 찾는다.

에이전트는 목표를 달성할 때까지 같은 과정을 반복한다.

요청
계획
실행
확인
보고

확인 단계에서 문제가 발견되면 다시 계획하고 실행한다. 이 반복을 에이전트 루프라고 한다.

터미널은 글자로 명령을 입력해 컴퓨터를 조작하는 창이다.

$ npx serve .
  Serving at http://localhost:3000

$ git commit -m "메인 페이지 추가"

에이전트는 서버 실행, 프로그램 설치, Git 작업을 터미널 명령으로 처리한다.

사용자가 명령을 직접 입력할 필요는 없으며, 에이전트가 실행한 명령은 작업 화면에서 확인할 수 있다.

에이전트가 승인 없이 실행할 수 있는 범위는 사용자가 정한다.

명령 실행, 파일 삭제, 외부 사이트 접속 같은 작업은 실행하기 전에 사용자에게 승인을 요청하도록 설정할 수 있다.

자동으로 실행하는 범위가 넓을수록 작업 속도는 빨라지지만, 의도하지 않은 변경이 생길 가능성도 커진다.

아티팩트는 에이전트가 작업 과정에서 남기는 기록이다.

작업 계획무엇을 어떤 순서로 할지 정리한 문서
작업 목록진행 상황을 표시한 체크리스트
변경 내역수정된 파일과 바뀐 내용
스크린샷과 녹화브라우저에서 결과를 확인한 기록

아티팩트를 보면 에이전트가 무엇을 했는지 코드를 읽지 않고도 파악할 수 있다.

대화는 서로 독립되어 있다.

새 대화를 시작한 에이전트는 이전 대화의 내용을 알지 못한다. 다음 대화에서도 필요한 정보는 README.md나 지침 파일처럼 프로젝트 폴더 안의 파일로 남긴다.

대화가 길어져 응답이 부정확해지면, 현재 상태를 파일로 정리하게 한 뒤 새 대화에서 이어서 작업한다.

여러 에이전트에게 동시에 작업을 맡길 수 있다.

Antigravity 2.0은 여러 대화를 동시에 실행하고 한 화면에서 관리한다. 서로 다른 작업을 나누어 맡기거나, 같은 작업을 여러 방식으로 맡긴 뒤 결과를 비교해 선택할 수 있다.

여러 에이전트가 같은 파일을 동시에 수정하면 서로의 변경 내용을 덮어쓸 수 있다.

결과의 품질은 요청의 크기와 확인의 빈도에 따라 달라진다.

작게 요청한다한 번에 하나의 변경을 요청한다.
직접 확인한다단계마다 결과를 브라우저에서 확인한다.
구체적으로 전달한다기대한 결과와 실제 결과, 스크린샷, 오류 메시지를 함께 전달한다.
저장한다잘 작동하는 상태를 커밋으로 저장한다.
다시 시작한다같은 문제가 반복되면 이전 커밋으로 되돌리고 새 대화에서 시도한다.

Git과 GitHub

Git은 파일의 변경 이력을 기록하는 버전 관리 도구다.

Git으로 관리하는 프로젝트 폴더를 저장소(repository)라고 한다. 변경 이력은 저장소 안의 숨김 폴더 .git에 저장된다.

저장한 시점의 상태는 언제든 다시 확인하고 되돌릴 수 있다.

커밋은 특정 시점의 프로젝트 상태를 저장한 기록이다.

커밋마다 고유한 번호와, 무엇을 바꿨는지 설명하는 커밋 메시지가 붙는다. 배경색 변경이 마음에 들지 않으면 스크롤 효과를 추가한 시점으로 되돌릴 수 있다.

Git의 주요 용어

저장소 repositoryGit이 변경 이력을 관리하는 프로젝트 폴더

되돌리기 revert, reset이전 커밋의 상태로 돌아가는 것
브랜치 branch기존 작업에 영향을 주지 않고 별도로 진행하는 작업 흐름

배포

배포는 내 컴퓨터의 파일을 인터넷 서버에 올려 누구나 접속할 수 있게 하는 일이다.

localhost:3000내 컴퓨터에서만 열린다.
web-practice.pages.dev인터넷에 연결된 누구나 열 수 있다.

HTML, CSS, JS, 이미지로만 이루어진 사이트를 정적 사이트라고 한다.

정적 사이트는 서버가 별도의 처리 없이 파일을 그대로 전달하므로, 무료 호스팅 서비스에 올릴 수 있다.

로그인이나 데이터 저장처럼 서버의 처리가 필요한 기능에는 별도의 서비스가 필요하다.

Cloudflare Pages에는 폴더를 끌어다 놓아 배포할 수 있다.

  1. Cloudflare 계정을 만든다.
  2. 대시보드에서 Workers & Pages 메뉴를 연다.
  3. Pages 프로젝트를 만들고, 직접 업로드를 선택한다.
  4. 프로젝트 이름을 정하고 프로젝트 폴더를 끌어다 놓는다.
  5. 배포가 끝나면 https://프로젝트이름.pages.dev 주소가 생긴다.

사이트를 수정한 뒤에는 다시 배포한다.

직접 업로드수정한 폴더를 다시 업로드하면 새 버전이 배포된다.
GitHub 연결GitHub 저장소를 연결하면 푸시할 때마다 자동으로 배포된다.

배포 기록이 남기 때문에, 문제가 생기면 대시보드에서 이전 버전으로 되돌릴 수 있다.
