# 실기기 확인 체크리스트

개발 기계에는 터치 기기가 없거나 화면을 보지 못할 수 있어서, 아래는 사람이 실제 기기로 직접 봐야 하는 것만 모았다. 항목마다 **방법**, **기대**, **실패하면 알려 줄 것** 순서다.

## 이미 자동 검증됨(다시 볼 필요 없음)
- 리모컨 페어링(1회용 코드, 재사용 거절), 이동, 타이머, 가리기, 연결 끊김 안내와 새 티켓 재연결(끊김은 흉내 낸 것), QR 해독(macOS CoreImage로 실제 디코드), 모든 버튼 44px 이상
- 터치 히트 영역 규칙(레이아웃 불변, 확장 영역 적중), 키보드 흐름, 접근성(axe), 390px 가로 넘침
- 게시 중인 덱 휴지통 안내, 그라디언트의 엔진, 번들, 인쇄, PDF 셰이딩 바이트

## 1. iPhone Safari 리모컨
준비: 앱을 휴대폰이 닿는 HTTPS 주소(예: Tailscale 등으로 연 `https://<내 기계 이름>.<tailnet>.ts.net:<포트>`, 열 주소는 `SLIDEKIT_ALLOWED_HOSTS`에 적는다)로 열고 발표자 화면에서 **Remote**를 누른다. 127.0.0.1로 열면 휴대폰이 닿지 못한다.

| 확인 | 방법 | 기대 | 실패하면 |
|---|---|---|---|
| QR 스캔 | 카메라 앱으로 대화상자의 QR을 비춘다 | 링크가 뜨고 열면 슬라이드 번호와 노트가 보인다 | QR 아래 주소의 앞부분(호스트와 포트)과 화면에 뜬 문구 |
| 화면 잠금 뒤 재연결 | 전원 버튼으로 잠그고 10초 뒤 푼다 | 잠깐 `Connection lost` 후 저절로 돌아오고 Next가 동작한다 | 푼 뒤 화면 문구와 걸린 시간 |
| 화면 꺼짐 방지 | iOS 자동 잠금을 30초로 하고 3분 둔다 | 리모컨 화면이 꺼지지 않는다 | iOS 버전 |
| 지연 | Next를 연달아 탭한다 | 발표자 화면이 0.3초 안팎에 따라온다(셀룰러나 DERP 경유면 더 걸릴 수 있다) | Wi-Fi인지 셀룰러인지와 체감 지연 |
| 노치와 하단 바 | 세로와 가로로 돌려 본다 | 버튼이 노치와 홈 인디케이터에 안 가리고 Next/Previous가 끝까지 눌린다 | 기종과 방향, 스크린샷 |

## 2. 터치 영역(iPhone, 덱 목록과 발표자 화면)
- 방법: 목록에서 카드 본문, 카드의 Present와 `...` 아이콘, 헤더 아이콘(검색, 정렬, 휴지통, 보기, New deck)을 손가락으로 눌러 본다.
- 기대: 카드 본문은 열기, 아이콘은 그 동작만 실행된다. 옆 버튼이나 카드가 잘못 눌리지 않는다.
- 실패하면: 어느 화면, 어느 버튼을 누르려다 무엇이 눌렸는지(스크린 녹화가 가장 좋다).

## 3. 새 기계에서 첫 실행
- 방법: 새 폴더에서 `git clone git@github.com:vynnlee/slidekit.git && cd slidekit && bun install && bun run slidekit`, 열린 앱에서 New deck을 만든다. 이어서 `bun run slidekit pdf <덱 폴더 이름>`을 실행한다(Chrome이 설치돼 있고 `SLIDEKIT_CHROME`은 지정하지 않는다).
- 기대: 앱이 http://127.0.0.1:3200에 열리고 덱이 만들어진다. PDF는 시스템 Chrome을 찾아 `dist/`에 생긴다.
- 실패하면: 터미널 출력 마지막 20줄. PDF는 `Chrome을 찾지 못했다` 같은 문구와 Chrome 설치 위치.

## 4. 그라디언트 PDF
- 방법: 편집기에서 채우기를 그라디언트로 한 덱의 PDF를 만들어 Chrome과 Acrobat에서 연다.
- 기대: 색이 앱 화면과 같다(투명한 스톱 포함). macOS 미리보기는 그라디언트를 검게 그릴 수 있고, 이건 알려진 한계다.
- 실패하면: 열어 본 앱 이름과 버전, 스크린샷.

## 5. 암호 덱 속도 제한
- 방법: Worker는 2026-10-15에 배포되어 있다. 비밀번호 덱을 하나 올리고(`bun run deploy <덱>`, 비밀번호를 물어보며 올리는 일은 직접 실행), 시크릿 창에서 틀린 비밀번호를 연달아 입력한다. 기존 비밀번호 덱의 쿠키는 배포로 무효가 되어 첫 접속에서 비밀번호를 다시 입력한다.
- 기대: 5번째 시도 뒤 15분 동안 잠긴다는 안내가 나오고 올바른 비밀번호도 그동안 막힌다.
- 실패하면: 몇 번째에 막혔는지와 화면 문구, 배포 주소.

## 6. 큰 덱 발표 리허설(53장 워크숍 덱)
- 방법: Present로 발표를 시작해 T(타이머), `+` `-`(노트 크기), PgUp과 PgDn(노트 스크롤), B와 W(청중 창에서 가리기), F(전체 화면), Cmd K(팔레트)를 써 본다.
- 기대: 각 키가 동작하고, 청중 창과 발표자 화면의 장 위치가 같다. 가리기를 풀면 슬라이드가 돌아온다. 전체 화면은 브라우저가 거절하면 안내가 뜬다.
- 실패하면: 어느 키가 무엇을 했는지와 걸린 시간(몇 장째에서 느려졌는지).

## 7. 프로젝터 연결과 청중 창 전체화면
- 방법: 외장 화면을 연결하고 Present를 눌러 화면 관리 권한을 허용한다.
- 기대: 청중 창이 외장 화면에 열리고 전체 화면이 된다. 안 되면 `Fullscreen blocked. Press F in the presentation window.`가 뜨고 그 창에서 F로 된다. 화면 선택 목록에서 다른 화면을 고르면 그 화면으로 열린다.
- 실패하면: 연결한 화면 수와 위치, 화면에 뜬 안내 문구.
