# 마일스톤 (Artifact 모방 추천안)

2026-10-18 사용자 승인. 출처: paperplane 리서치(Claude Artifacts 2024-2026)에서 모방할 것을 고른 목록. 철학은 **덱과 엔진은 바닐라 HTML/CSS/JS 완결, 새 의존성 없음, 편집기 앱 의존성은 무관**이다. 새 기능은 구현 전에 설계를 쓰고, 푸시와 외부 배포는 lead가 게이트 뒤에 한다(Worker 배포와 `unpublish`는 사용자 승인 필요).

## M1 수정 프로토콜과 존재 효과
- 설계: `spec/AGENT-PRESENCE.md`(이벤트 스키마), `/tmp/slidekit-agent-fx/DESIGN.md`(화면, 구현 시 `spec/`로 옮김).
- 합격: `slidekit_edit`가 유일성, 원자성, revision 충돌, 경로 이탈을 검사하고 린트 결과를 돌려준다. 도구를 안 쓴 직접 수정은 파일 감시로 슬라이드 단위 효과가 나온다. 효과는 편집기만(덱 엔진과 발표 화면 불변), 사용자의 선택과 포커스를 바꾸지 않는다. 움직임 줄이기, 스크린 리더 안내, 요소 100개와 CPU 4배에서 긴 작업 0건.

## M2 발행 보안 강화와 호환 검사
- 2a(app-dev): 배포 Worker가 덱 응답에 CSP 헤더를 붙인다. 허용은 덱이 쓰는 글꼴 호스트와 자기 출처뿐이고 `connect-src`는 자기 출처만이다. 기존 로컬 리허설과 연기 시험(`deploy` 단계)에 헤더 검사를 추가한다. **Worker 실제 배포는 사용자 승인 뒤.**
- 2b(engine-dev): `slidekit doctor <덱> --artifact`와 `lint` 규칙. 검사: 단일 파일 번들 가능, 상대 경로와 허용 호스트 밖 외부 자원 없음, 렌더 크기 16 MiB 이하, `localStorage`와 `sessionStorage`와 `indexedDB` 사용 없음, 외부로 나가는 `fetch`와 `WebSocket` 없음. 결과는 "Artifact로 올릴 수 있음/없음과 이유"로 요약.
- 합격: 가이드 덱과 워크숍 덱의 번들이 검사를 통과하거나 이유가 설명된다. CSP 아래에서도 번들 덱이 정상 동작한다(브라우저 시험).

## M3 `deck.md` 쌍
- 3a(engine-dev): `slidekit outline`을 번들과 배포에서 재사용해 `deck.md`를 만든다. **발표자 노트는 기본 제외**(공개 유출 방지), `--notes`를 줄 때만 포함한다.
- 3b(app-dev): 배포가 `deck.html` 옆에 `deck.md`를 올리고, 덱 `<head>`에 `<link rel="alternate" type="text/markdown">`을 넣는다(번들 단계에서만, 원본 덱은 그대로). 앱의 배포 완료 화면에 "Copy agent prompt"(URL과 `curl` 명령) 단추.
- 합격: 번들 덱이 알터네이트 링크를 갖고 `deck.md`가 노트 없이 내용을 무손실로 담는다. 외부 의존성 추가 0.

## M4 발표 화면 실시간 갱신
- app-dev: 에이전트가 덱 파일을 고치면 발표자 화면과 청중 창과 리모컨이 **현재 슬라이드와 단계 위치를 유지한 채** 갱신된다. 현재 슬라이드가 지워졌으면 가장 가까운 슬라이드로.
- 합격: 위치 유지, 깜빡임 최소, 발표 중 갱신이 사용자를 방해하지 않게 옵션 또는 알림(바로 반영/알림만), 무작위 이동 퍼즈와 충돌 없음, 누수 0.

## M5 코멘트 자동 처리 폭주 방지
- channel-dev: 코멘트 활성화와 자동 처리에 시간당 상한(기본 60), 중단 장치(패널의 Pause와 상태 표시), 상한 도달 시 알림. 합격: 상한 시험, 중단과 재개 시험, 기존 코멘트 흐름 불변.
