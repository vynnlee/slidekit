# 에이전트 존재감 효과 (편집기 쪽 표현, 구현됨: 현재 규칙은 SPEC 9.8)

상태: 구현됨. 이벤트 스키마는 `spec/AGENT-PRESENCE.md`(확정)를 따르고, 아래 3절의 초안 스키마는 확정본으로 대체됐다(`ttlMs`는 `ttl`(ms), `changes`는 `changed:[{slide, excerpt}]`, `agent`는 이름 문자열, 변경 요소는 excerpt로 찾는다). UI 문구는 영어, 설명은 한국어. 사용자 결정: 효과는 **커서 + 반짝임 + 변경 강조**, 범위는 **편집기만**(덱 엔진, 발표 화면, 번들은 건드리지 않는다), 새 슬라이드를 **강제로 선택하지 않는다**. 스키마(`agent.edit.start/done/fail`)는 channel-dev의 `spec/AGENT-PRESENCE.md`가 정하며, 아래 3절의 가정은 그 문서가 나오면 맞춘다.

## 0. 요약

- 에이전트가 슬라이드를 고치는 동안 캔버스 **위 오버레이**(`pointer-events:none`, iframe 안은 건드리지 않음)에 `Claude` 라벨이 붙은 **커서**가 대상 요소로 부드럽게 움직이고, 슬라이드에는 **테두리 광채와 점 격자 펄스**가 쓸고 지나간다. 필름스트립의 그 슬라이드 썸네일에도 작은 펄스, 다른 슬라이드를 고치는 중이면 선택을 바꾸지 않고 필름스트립 헤더에 `Claude is editing slide 3` 칩과 `Follow` 단추만 둔다.
- 끝나면(`done`) 파일 변경을 **기존 외부 변경 반영 경로**(`deck-changed` → `check()` → `load(keepSel)`)로 불러와 캔버스를 제자리에서 갱신(iframe 깜빡임 없음)한 뒤, **바뀐 요소를 1.2초 한 번 번쩍여** 보인다.
- 충돌은 기존 규칙(편집 중이면 `File changed outside the editor`: Reload, Overwrite) 그대로이고 존재감은 상태 칩만 바꾼다.
- 접근성: `aria-live=polite`, `prefers-reduced-motion`이면 이동과 반짝임 없이 정지 테두리와 칩만, 색에 의존하지 않음(아이콘, 점선, 글자), 포커스 이동 없음.
- 성능: transform와 opacity 애니메이션만(합성기), `will-change`는 효과 중에만, 대기 중 비용 0, 이벤트 폭주는 합치고 TTL로 정리, 변경 강조는 최대 12개.

## 1. 구성 요소와 위치

| 요소 | 위치 | 비고 |
|---|---|---|

| 알림 | `role="status"` 시각적으로 숨김 영역 1개 | 3절 문구 |

## 2. 에이전트 커서

- 모양: Figma 협업 커서처럼 화살표(작은 SVG)에 `Claude` 라벨 칩이 붙는다. 칩 안에는 반짝임 아이콘(✦)과 이름. 이름은 이벤트의 `agent.name`.
- 대상 위치: 이벤트의 앵커(슬라이드 안 CSS 경로, `byPath`와 같은 형식)로 캔버스 요소를 찾아 `canvas.anchor(el)`(이미 있음)로 화면 좌표를 한 번 구한다. 앵커가 없거나 못 찾으면 슬라이드 중앙. 요소가 슬라이드 밖이면 가장자리에 붙인다.
- 이동: `transform: translate3d(x,y,0)`만 바꾸고 `transition: transform 650ms cubic-bezier(.22,1,.36,1)`. 줌이나 창 크기가 바뀌면 같은 앵커로 한 번 다시 계산한다(ResizeObserver는 스테이지 한 개, 프레임당 한 번).
- 도착: 요소 외곽선 광채 오버레이(요소 크기의 `div`, `box-shadow`는 정지 상태로 두고 `opacity`만 애니메이션) 800ms, 편집 중에는 은은한 숨쉬기(opacity 0.35 ↔ 0.7, 2.4s).
- 여러 에이전트: 이름별 색을 팔레트에서 고정 배정(이름 해시, 6색, 모두 대비 4.5:1 이상의 글자색과 짝), 커서가 겹치면 라벨을 위아래로 어긋나게 쌓는다. 색은 구분 보조일 뿐 칩 글자(이름)와 아이콘이 기본 구분이다.
- 사용자와 겹침: 커서는 `pointer-events:none`이라 클릭을 가로채지 않고, 사용자가 같은 요소를 글자 편집 중이면(`contenteditable`) 커서는 근처 모서리에 머물고 광채는 외곽선만(내용을 가리지 않음).

## 3. 이벤트 스키마 가정 (channel-dev 확정 전 초안)

SSE `/api/events`의 이벤트(기존 `deck-changed`와 같은 통로, `deck` 필드로 걸러냄):

| 이벤트 | 필드 | 뜻 |
|---|---|---|
| `agent.edit.start` | `id`(세션), `agent {id, name}`, `deck`, `slide`(1부터), `anchor?`(경로), `ttlMs`(기본 30000, 최대 120000) | 수정 시작. 같은 `id`를 다시 보내면 TTL 연장 |
| `agent.edit.update` (선택) | `id`, `slide?`, `anchor?` | 대상이 바뀜(커서 이동) |
| `agent.edit.done` | `id`, `slides?`, `changes?`(`{slide, path}` 목록), `count?` | 완료. 파일은 이미 써졌거나 곧 `deck-changed`가 온다 |
| `agent.edit.fail` | `id`, `reason?` | 실패 또는 취소 |

규칙: 알 수 없는 필드는 무시, `start` 없이 온 `done/fail`은 짧게 알림만, TTL이 지나면 말없이 정리(실패 칩 없음, 로그만). 슬라이드 번호는 `start` 시점의 번호이고 슬라이드가 삽입, 삭제되면 `done`의 `diffDecks` 결과로 다시 매핑한다.

## 4. 수정 중 슬라이드 효과(캔버스)

레이어 구성(아래에서 위): ① 슬라이드 테두리 광채 ② 점 격자 펄스 ③ 요소 광채 ④ 커서. 전부 CSS(마스크된 그라디언트, opacity, transform)이고 JS 루프가 없다.

- **테두리 광채**: 스테이지 크기의 `div`, 안쪽 1px 테두리와 `box-shadow`를 정지 상태로 두고 `opacity` 0.25 ↔ 0.6 숨쉬기(2.4s). 에이전트 색.
- **점 격자 펄스**("매트릭스" 느낌을 절제해서): 18px 간격의 점(`radial-gradient(circle, color 1px, transparent 1.6px)`) 레이어 4~5장을 슬라이드를 세로 띠로 나눈 **정지 마스크**(`mask-image: linear-gradient(90deg, transparent, #000 40%, transparent)`)로 자르고, 띠마다 `animation-delay`를 어긋나게 한 **opacity 애니메이션**(0 → 0.5 → 0, 2.8s)을 걸어 왼쪽에서 오른쪽으로 파동이 쓸고 가는 것처럼 보인다. 마스크와 격자는 정지, 움직이는 것은 opacity뿐이라 합성기만 쓴다. 점 색은 에이전트 색 40% 투명.
- 효과 중에만 레이어에 `data-on` 클래스를 달고 `will-change: opacity, transform`을 켠다. 끝나면 속성을 제거하고 레이어를 DOM에서 뺀다.
- 필름스트립 썸네일: 타일에 `data-agent="<색>"`, 모서리 점(고정)과 펄스 링(pseudo-element, opacity 0.2 ↔ 0.7). 효과가 끝나면 링은 사라지고 점은 `updated` 표시와 같은 4초 규칙을 따른다.
- 다른 슬라이드를 고치는 중: 캔버스에는 아무것도 그리지 않는다. 필름스트립 타일 펄스와 헤더 칩만. **슬라이드 선택은 절대 바꾸지 않는다.** `Follow`를 눌렀을 때만 `setIndex`.

## 5. 완료 처리: 변경 강조와 캔버스 갱신

1. `done` 수신 → 존재감 저장소가 세션을 `finishing`으로 바꾸고 광채, 격자, 커서는 300ms 안에 사라진다.
2. 파일 반영: `deck-changed`는 기존 경로(`check()` → `load(folder, index, true)`)를 그대로 쓴다. `done`이 파일 변경 이벤트보다 먼저 오면 `done` 처리에서 `check()`를 한 번 직접 부른다(중복 호출은 저장소가 합침). **새 갱신 경로를 만들지 않는다**: 바뀐 슬라이드만 제자리에서 갈아 끼우는 기존 동작이라 iframe 깜빡임이 없다.
3. 변경 요소 찾기: 이벤트의 `changes`가 있으면 그대로, 없으면 `load` 직전과 직후의 슬라이드 HTML을 요소 경로 단위로 비교해 **가장 안쪽에서 바뀐 요소**(속성이나 글자가 바뀌었거나 새로 생김)를 고른다. 순수 함수 `changedPaths(oldHtml, newHtml)`(단위 테스트). 12개를 넘으면 요소 대신 슬라이드 전체를 한 번 번쩍인다.
4. 강조: 요소마다 에이전트 레이어에 외곽선 `div`를 만들어 `opacity 0 → 1 → 0`(1.2초, 외곽선 2px + 부드러운 광채) 한 번, 끝나면 DOM에서 제거. 첫 요소가 화면 밖이면 스크롤하지 않고 칩에 `View` 단추만(사용자 시야를 빼앗지 않음).
5. 칩과 알림: `Claude finished editing slide 3 · 2 changes`(4초 뒤 사라짐), 기존 일반 토스트(`Slide 3 updated`)는 같은 세션이면 합쳐서 한 번만(중복 낭독 방지). Undo 기록이 지워졌다는 기존 안내는 유지.
6. `fail`: 효과를 걷고 칩 `Claude couldn't finish editing slide 3`(6초). 변경은 없으니 강조 없음.

## 6. 충돌

- 사용자가 편집 중(`dirty`)일 때 파일이 바뀌면 기존 `setChanged(true)`(`File changed outside the editor` 띠, Reload/Overwrite)를 그대로 쓴다. 존재감은 칩만 `Claude edited slide 3. Reload to see the changes.`로 바꾸고 변경 강조는 불러온 뒤에만(`Reload`를 누르면 같은 강조).
- 같은 슬라이드를 사용자가 글자 편집 중이면 커서와 요소 광채는 보이되 내용 위에 그리지 않고(외곽선만), 입력 포커스와 선택은 건드리지 않는다.
- 사용자가 저장을 누른 직후 충돌(409)은 기존 처리 그대로.

## 7. 접근성

- 시각적으로 숨긴 `role="status"`(`aria-live=polite`, `aria-atomic`) 하나: `Claude is editing slide 3`, `Claude finished editing slide 3, 2 changes`, `Claude couldn't finish editing slide 3`. 효과 장식 레이어는 모두 `aria-hidden`. 연속 `start`는 같은 문구를 반복 낭독하지 않는다(세션당 한 번).
- `prefers-reduced-motion: reduce`: 커서 이동, 숨쉬기, 격자 파동, 변경 번쩍임 모두 없음. 정지한 슬라이드 테두리, 대상 요소 정지 외곽선, 칩만 보이고 완료 강조는 1.2초 정지 외곽선(애니메이션 없음)으로 대체. (`matchMedia` 변경도 즉시 반영.)
- 색에 의존하지 않음: 칩 글자(이름), 아이콘(✦), 점선 외곽선(에이전트), 실선 외곽선(사용자 선택)처럼 모양이 다르다. 색 대비 4.5:1.
- 포커스를 가져가지 않는다: 어떤 효과도 `focus()`를 부르지 않고, `Follow`와 `View`는 평범한 단추(탭 순서에 자연스럽게)다.

## 8. 성능 예산

| 항목 | 예산 | 방법 |
|---|---|---|
| 대기 중(세션 없음) | 비용 0 | 구독만 있고 타이머, 관찰자, 애니메이션 없음. 레이어는 세션이 생길 때 만들고 끝나면 제거 |
| 효과 중 프레임 | 긴 작업(50ms 초과) 0건(요소 100개 슬라이드, CPU 4배) | transform와 opacity만, 레이아웃 읽기는 이벤트당 한 번(앵커 좌표), `will-change`는 효과 중에만 |
| 입력 지연 | 효과 켜짐/꺼짐에서 타이핑, 드래그 지연 차이 없음 | 오버레이는 `pointer-events:none`, JS 루프 없음, 편집기 React 상태를 건드리지 않음(외부 저장소) |
| 이벤트 폭주 | 초당 100건이 와도 프레임당 1회 처리 | rAF로 합치고 (에이전트, 슬라이드)별로 마지막 값만 반영, 세션 최대 3개(나머지는 칩 `+2`) |
| 정리 | 효과 후 DOM 0, 리스너 누수 0 | 공유 TTL 타이머 하나, 세션 종료 때 레이어와 요소 제거, 컴포넌트 해제 때 구독 해제 |
| 변경 강조 | 요소 최대 12개 | 초과 시 슬라이드 전체 한 번 |

## 9. 시험 계획

- 단위(`agent-presence`): 리듀서(start, update, done, fail, TTL 만료, 같은 id 재전송 합치기, 세션 상한), `changedPaths`(속성, 글자, 추가, 삭제, 중첩, 12개 초과), 색 배정 안정성.
- e2e(가짜 이벤트 주입, `editor-agent-fx`): 실제 SSE로 이벤트를 쏘는 시험용 경로(channel-dev의 스키마가 정한 발행 수단, 없으면 서버에 시험 전용 발행 엔드포인트를 요청) 또는 저장소의 `ingest`를 `window`에 노출하는 e2e 전용 훅. 확인: 시작 → 커서가 앵커 위치로 이동(transform 값), 슬라이드 광채와 격자 레이어 존재, 다른 슬라이드면 캔버스 레이어 없음과 칩과 `Follow`, 선택이 바뀌지 않음, `Follow`가 슬라이드 이동, 완료 후 효과 DOM 제거와 `will-change` 없음, 파일을 바꿔 쓴 뒤 바뀐 요소에 강조가 1.2초 뜨고 사라짐, iframe 재생성 없음, TTL 만료 정리, `fail` 칩, 리스너 수 증가 0(시작/끝 100회 반복 후), 이벤트 폭주(500건) 후 상태 수렴.
- reduced-motion: 에뮬레이션에서 애니메이션 이름이 없고(`getAnimations()` 0) 정지 테두리와 칩만.
- 접근성: 효과 중 axe(serious, critical 없음), `role=status` 문구, 포커스 불변(`document.activeElement` 그대로).
- 충돌: 사용자가 편집 중일 때 외부 변경 → 기존 띠가 뜨고 강조는 Reload 뒤, 글자 편집 중 포커스 유지.
- 성능: `editor-anim-perf`와 같은 방식으로 요소 100개 슬라이드에서 효과 중 긴 작업과 프레임 간격, 입력 지연(타이핑 시뮬레이션) 측정(CPU 4배).

## 11. 위험과 열린 문제

1. **이벤트가 `done`보다 늦거나 빠름**: `done` 처리에서 `check()` 한 번 + 파일 이벤트가 합쳐지게 한다(저장소 합치기).
2. **앵커가 낡음**: 앵커 경로는 `start` 시점의 DOM 기준이라 도착 시 못 찾을 수 있다 → 슬라이드 중앙으로 폴백.
3. **여러 슬라이드를 한 번에 수정**: `slides` 목록으로 필름스트립 타일마다 표시, 캔버스는 현재 슬라이드만.
4. **저전력 기계(mac-cloud)에서 반복 애니메이션**: 숨쉬기와 파동은 opacity뿐이지만 CPU 4배 시험에서 한도를 확인하고, 넘으면 파동을 끄고 테두리만 남기는 단계적 축소(`data-lite`)를 둔다.
5. **스키마 확정 대기**: 3절 이벤트 이름과 필드가 바뀌면 저장소 어댑터만 고친다(렌더는 내부 모델만 안다).

## 12. 구현 순서(스키마 확정 뒤)

(1) 저장소와 `changedPaths` 단위 테스트 → (2) 이벤트 어댑터(SSE) → (3) 에이전트 레이어(광채, 격자, 커서) → (4) 필름스트립 표시와 칩, `Follow` → (5) 완료 처리와 변경 강조, 토스트 합치기 → (6) reduced-motion, 접근성, 성능 → (7) e2e(가짜 이벤트), 문서(SPEC, AGENT-PRESENCE 편집기 쪽 절).
