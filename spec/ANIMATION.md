# 단계 애니메이션 설계

슬라이드 안에서 요소가 단계마다 나타나고 사라지는 방식과 편집기 화면의 설계다. 현재는 `data-step`(등장)과 이름 있는 효과 6종(`data-step-effect`)이 있고, 이 문서는 퇴장, 지연, 효과 값을 파일 형식으로 일반화하고 하단 Animation 패널로 편집하는 안을 정한다. 설계 문서이며 코드는 이 문서가 확정된 뒤에 바꾼다. 2026-10-17에 v2 개정안을 더했다(빈 단계 압축, 퇴장 전용 값, 관계 미저장, 값 검증, 타임라인이 읽는 정보와 전환 관측 계약). v2로 바뀐 곳은 제목에 `(v2)`를 달았고, 승인 전에는 푸시된 동작이 기준이다. UI 문구는 영어, 이 문서는 한국어다. 지금 동작의 기준은 SPEC 6.3절이고, 확정되면 6.3절로 옮긴다.

## 1. 원칙

1. **프리셋 이름은 파일에 저장하지 않는다.** 파일에는 HTML 속성(`data-step`, `data-step-out`)과 CSS 변수(`--sk-away-*`, `--sk-step-ms`, `--sk-step-delay`)만 남는다. Fade, Rise 같은 이름은 편집기의 빠른 선택 단추일 뿐이고 누르면 변수 값이 채워진다. 레이아웃 프리셋을 걷어낸 것과 같은 방향이다: 우리는 HTML 구조와 값만 정한다.
2. **순서의 유일한 기준은 단계 번호다.** 요소의 DOM 순서, 편집기의 Layers 순서는 재생 순서와 무관하다. 같은 번호는 같은 단계에 함께 일어난다.
3. **엔진 JS는 단계 번호만 계산하고 모양은 CSS가 만든다.** 엔진은 현재 단계에서 각 요소가 보이는지(`data-away` 속성의 유무)만 정한다. 이동 거리, 투명도, 흐림, 시간, 곡선은 모두 CSS 변수다.
4. **파일은 사람이 읽고 고칠 수 있어야 한다.** 편집기 없이 `data-step="3"` 한 줄과 변수 몇 개만으로 같은 결과가 나온다. AI가 덱을 만들 때도 이 두 속성과 변수만 알면 된다.
5. **작게 시작하고 닫지 않는다.** v1은 요소당 등장 1번과 퇴장 1번이다. 강조와 재등장은 넣지 않되 형식이 막지 않게 둔다(3.5절).

## 2. 모델

### 2.1 요소의 두 상태

요소는 보이는 상태(기본)와 벗어난 상태(away state) 두 가지만 가진다. 벗어난 상태는 요소 하나의 변수 다섯 개로 정한다.

| 변수 | 뜻 | 기본값 |
|---|---|---|
| `--sk-away-opacity` | 벗어난 상태의 투명도 | `0` |
| `--sk-away-x` | 가로 이동 | `0px` |
| `--sk-away-y` | 세로 이동 | `20px` |
| `--sk-away-scale` | 배율 | `1` |
| `--sk-away-blur` | 흐림 | `0px` |

기본값은 지금의 기본 효과(`rise`: 투명도 0, 위로 20px 올라오기)와 같다. 변수는 요소의 `style` 속성이나 덱 CSS의 클래스에서 정한다. 덱 전체의 기본을 바꾸려면 `:root`에서 정한다.

### 2.2 단계 번호

| 속성 | 뜻 |
|---|---|
| `data-step="N"` | N단계부터 보인다(등장). 기존 속성 그대로다. N은 2 이상 정수. |
| `data-step-out="M"` | M단계부터 사라진다(퇴장). 신규. M은 2 이상 정수이고 N이 있으면 M > N. |

- 보이는 구간은 `N ≤ 단계 < M`이다. N이 없으면 처음부터 보이고(N = 1), M이 없으면 끝까지 보인다.
- 등장 없이 퇴장만 둘 수 있다: 처음에 보이다가 M단계에서 사라진다.
- 단계 1이 슬라이드의 처음 상태다. 단계 1에서 보이지 않는 요소는 N ≥ 2인 요소다.
- **(v2) 번호는 순서만 뜻한다.** 쓰이는 번호의 집합을 오름차순으로 세어 클릭을 만든다(1, 3, 7이면 클릭 3번). 번호에 빈칸이 있어도 빈 클릭은 없다(3.7절). `2, 3, 4`처럼 촘촘한 덱은 이전과 같다.

### 2.3 시간

| 변수 | 뜻 | 기본값 |
|---|---|---|
| `--sk-step-ms` | 전환 시간 | `360ms`(지금과 같다) |
| `--sk-step-delay` | 같은 단계 안에서 이 요소만 늦추는 시간(앞으로 가는 방향에서만) | `0ms` |

- 곡선은 전역 `--sk-ease` 하나다. 요소별 곡선은 v1에 넣지 않는다.
- **With previous**와 **After previous**는 저장하지 않는다. 같은 단계 번호 안에서 지연과 시간 숫자만 있다(2.6절).

### 2.4 등장과 퇴장의 값 (v2)

요소는 벗어난 상태가 두 곳일 수 있다: 등장 전과 퇴장 뒤. v1은 둘이 같은 변수 한 벌을 썼고, v2는 퇴장 뒤에 다른 값을 줄 수 있다. 퇴장 변수가 없으면 등장 변수를 따라가므로 지금 덱은 그대로 동작한다.

| 퇴장 변수 | 없을 때 따라가는 변수 | 뜻 |
|---|---|---|
| `--sk-out-opacity` | `--sk-away-opacity` | 퇴장 뒤 투명도 |
| `--sk-out-x` | `--sk-away-x` | 가로 이동 |
| `--sk-out-y` | `--sk-away-y` | 세로 이동 |
| `--sk-out-scale` | `--sk-away-scale` | 배율 |
| `--sk-out-blur` | `--sk-away-blur` | 흐림 |
| `--sk-out-ms` | `--sk-step-ms` | 퇴장 전환 시간 |
| `--sk-out-delay` | `--sk-step-delay` | 퇴장을 클릭 시점보다 늦추는 시간 |

- 폴백은 CSS `var(--sk-out-x, var(--sk-away-x, 0px))` 체인이다. 엔진 JS는 새 계산을 하지 않는다.
- 엔진은 퇴장한 요소에 `data-away="out"`을, 등장 전 요소에 `data-away=""`를 붙인다(지금은 값 없는 속성). 속성의 있고 없음은 그대로 쓰므로 `data-shown`과 `data-away`의 배타 검사는 변하지 않는다. CSS는 `[data-away="out"]`일 때만 퇴장 변수를 읽는다. 편집기 캔버스도 퇴장 단계에는 `data-away="out"`을 써야 퇴장 모양이 그려진다.
- 전환에 쓰는 시간과 지연은 **어느 사건인가**로 정한다. CSS는 도착 상태와 슬라이드의 `data-step-run="back"`만 알면 되므로 아래 표로 고정한다.

| 사건 | 도착 상태 | 시간 | 지연 |
|---|---|---|---|
| 앞으로, 등장 | 보임 | `--sk-step-ms` | `--sk-step-delay` |
| 앞으로, 퇴장 | 퇴장 뒤 | `--sk-out-ms` | `--sk-out-delay` |
| 뒤로, 등장 취소 | 등장 전 | `--sk-step-ms` | 없음 |
| 뒤로, 퇴장 취소 | 보임 | `--sk-out-ms` | 없음 |

- 곡선은 전역 `--sk-ease` 하나다. 시간 값은 ms 단위가 규격이고, 엔진은 `s` 단위도 읽는다(3.8절).

### 2.5 이름 있는 효과와 기존 속성

- Fade, Rise, Scale, Blur, Slide는 편집기의 빠른 선택이다. 누르면 아래 값이 채워진다.

| 이름 | 채우는 값 |
|---|---|
| Fade | 투명도 0, 이동 0 |
| Rise | 투명도 0, y 20px |
| Slide | 투명도 0, x -32px |
| Scale | 투명도 0, 배율 0.92 |
| Blur | 투명도 0, 흐림 12px |

- 기존 `data-step-effect`(`rise`, `fade`, `left`, `scale`, `blur`, `none`)는 당분간 별칭으로 동작한다. 엔진 CSS가 위 표대로 변수를 대신 채우고(`none`은 `--sk-step-ms: 0ms`), 편집기가 그 요소를 편집하면 변수로 바꿔 쓰고 속성은 지운다. 제거 시점은 결정 사항이다(7절 결정 4).

### 2.6 시작 관계는 저장하지 않는다 (v2, 사용자 결정)

With previous와 After previous 같은 관계는 파일에 없다. 저장되는 것은 항목마다 **지연**(`--sk-step-delay` / `--sk-out-delay`, 클릭 시점부터 잰 절대 ms)과 **시간**(`--sk-step-ms` / `--sk-out-ms`) 숫자뿐이다. 엔진은 관계를 계산하지 않고, 관계 속성(`data-step-start` 등)은 두지 않는다(초안에 있던 안은 폐기).

- Together는 같은 지연, Then은 앞 막대의 끝(지연 + 시간)에 맞춘 지연값일 뿐이다. 편집기는 이 숫자를 막대 위치로 그리고, 목록의 Start 칸 같은 표시는 숫자에서 유도한다(저장하지 않는다).
- 앞 항목의 시간을 바꿔도 뒤 항목의 지연은 따라가지 않는다. 막대가 눈에 보이므로 사용자가 정렬을 직접 고친다. 편집기가 막대를 옮길 때 같은 조작에서 숫자를 다시 쓰는 것은 편집기의 선택이다.
- 장점은 런타임 추가 비용 0, 파일이 곧 동작(결정성), 낡은 값 문제 없음, 손으로나 AI가 `--sk-step-delay: 360ms` 한 줄로 고칠 수 있음이다.

## 3. 규칙

### 3.1 보임 구간과 단계 수 (v2)

- 요소는 `N ≤ 번호 < M`에서 보인다(번호는 속성에 적은 값). 보이지 않을 때 `data-away`가 붙고 CSS가 벗어난 상태를 입힌다.
- **클릭 단계는 쓰인 번호의 집합이 정한다**(3.7절). 슬라이드의 단계 수는 1 + 서로 다른 번호의 개수다. 퇴장 M도 번호에 들어간다.
- 한 요소에 등장 1개와 퇴장 1개까지다. 같은 요소에 `data-step`이 둘 있을 수는 없다(속성이 하나다).
- `SlideKit.stepper`로 등록한 슬라이드는 선언형 단계를 쓰지 않고 압축도 하지 않는다. 이 슬라이드의 단계 수는 지금처럼 `data-steps`와 요소 번호의 최댓값 중 큰 쪽이다(옛 규칙 그대로).

### 3.2 lint

- `data-step-out`이 정수가 아니거나 2 미만이면 오류, 같은 요소의 `data-step` 이하이면 경고(퇴장이 등장보다 앞서거나 같다: 보이는 구간이 없다).
- `data-step-out`이 쓰인 슬라이드에서 단계 번호에 빈 번호가 있으면 경고(지금 `data-step`의 빈 번호 경고와 같은 규칙을 퇴장에도 적용. v2에서 압축이 들어오면 이 경고는 없어진다).
- `data-step-effect`를 정보 수준으로 "별칭이다, 변수로 바꾼다"고 알리는 일과 `--sk-away-*` 값 형식 검사는 구현하지 않았다(후속, 결정 4의 시점 이후).
- 구현된 lint: `data-step-out`의 정수와 범위 오류, 퇴장이 등장보다 앞서거나 같음, 빈 단계 번호(퇴장 번호 포함), 한 슬라이드의 blur 3개 이상, 단계 요소가 있을 때 `data-steps`만으로는 오류가 아님.
- **(v2) 추가 규칙**:
  - 값 검증은 3.8절 표를 따른다(오류와 경고 구분).
  - 빈 번호 경고는 없앤다. 번호의 빈칸은 이제 정상이다(3.7절). 대신 `data-steps`가 선언형 단계 슬라이드(등록된 stepper 없음)에서 쓰이면 경고: 무시된다.
  - `--sk-out-*` 값이 있는데 `data-step-out`이 없으면 경고(쓰이지 않는 값).


### 3.3 움직임 줄이기

`prefers-reduced-motion: reduce`이면 전환 없이 상태만 바뀐다(시간 0, 지연 무시). 지금 규칙과 같다.

### 3.4 비활성 슬라이드와 퇴장 전환

- 퇴장은 투명도 전환이 끝난 뒤 `visibility: hidden`이 되어야 한다. 지금 등장 구현의 `visibility 0s`에 `--sk-step-ms`만큼 지연을 거는 방식을 그대로 쓴다(또는 `transition-behavior: allow-discrete`, 결정 사항 아님: 구현자가 더 단순한 쪽을 고른다).
- 슬라이드를 떠날 때(`adac0cd`의 규칙)는 퇴장 전환 도중이라도 즉시 숨긴다: 비활성 슬라이드의 모든 자손은 `visibility: hidden !important; transition: none !important`이므로 진행 중이던 퇴장 전환은 취소되고 다른 슬라이드 위에 남지 않는다. 떠나는 슬라이드의 페이드(`data-leaving`)가 도는 200ms 동안만 예외로 전환이 허용되지만 이 구간은 짧아 퇴장 전환이 끝나지 않아도 문제가 없다.
- 슬라이드에 들어올 때와 해시, 동기화로 점프할 때는 `data-step-instant`로 전환 없이 그 단계 상태로 바로 맞춘다(지금과 같다).

### 3.5 확장 여지(v2 이후, 이번에 만들지 않는다)

- 강조: `data-step-emph="K"`와 `--sk-emph-*` 변수로 단계 K에서 잠깐 키우거나 색을 바꾸기. 등장과 퇴장과 별도 속성이라 충돌하지 않는다.
- 재등장: `data-step-in2`처럼 이름을 하나 더 받는 방식. v1의 `data-step`, `data-step-out`은 그대로 둔다.
- 요소별 곡선: `--sk-ease-element`(이름 예약). 퇴장 전용 값은 v2에서 `--sk-out-*`로 들어왔다(2.4절, 예약했던 `--sk-away-out-*` 이름은 쓰지 않는다).

### 3.6 출력 매체별 동작

| 매체 | 동작 |
|---|---|
| 인쇄, PDF | 마지막 단계의 상태. 퇴장한 요소는 보이지 않는다(결정 3) |
| 전체 보기 썸네일 | 단계 1의 상태 |
| 편집기 캔버스 | 재생 헤드가 가리키는 단계의 상태(4절). `data-sk-show-steps`는 대체된다 |
| 발표자 화면 현재/다음 미리보기 | 엔진이 보고하는 현재 단계 상태, 다음 미리보기는 다음 단계 또는 다음 슬라이드의 단계 1 |
| 청중 창, 리모컨 | 동기화 메시지의 `(slide, step)` 그대로. 프로토콜은 바뀌지 않는다 |
| outline(Markdown) | 모든 요소의 글자를 단계와 무관하게 내보낸다 |
| 스크린 리더 | 지금처럼 앞으로 넘어갈 때 새로 나타난 요소의 글자를 읽는다. 퇴장은 읽지 않는다(결정 5). 압축 뒤에도 "이 클릭에 대응하는 번호의 등장 요소"를 읽고 안내문의 "단계 k / N"은 클릭 순위와 클릭 수다 |
| 해시와 `info` | 해시는 슬라이드 번호뿐(단계 없음). `info.steps`와 `info.slide`/`step`, 동기화 `(slide, step)`의 step은 모두 클릭 순위(1부터)다 |

**인쇄 규칙 변경의 영향.** 지금 PDF는 모든 `data-step` 요소를 보여 준다. 퇴장이 없으면 "모든 요소 보임"은 마지막 단계의 상태와 같아 달라지지 않는다. 퇴장이 생기면 둘이 달라진다: 퇴장하는 요소는 PDF에 나오지 않는다. 대안은 (a) 마지막 단계 상태(추천), (b) 단계마다 한 쪽씩 인쇄(쪽 수가 늘고 유인물이 커진다), (c) 첫 단계 상태(등장 요소가 빠진다)다. v1은 (a)이고 (b)는 `pdf --steps` 같은 선택 옵션으로 나중에 둘 수 있다.

### 3.7 빈 단계 압축 (v2)

**규칙.** stepper가 없는 슬라이드에서 엔진이 시작 때 한 번 계산한다.

1. 유효한 `data-step`(N ≥ 2)과 유효한 `data-step-out`(M, N이 있으면 M > N)의 값을 모은다.
2. 중복을 없애 오름차순으로 정렬한다: U = [u₁ < u₂ < … < uₖ].
3. 클릭 k(k = 2부터)는 번호 u_(k-1)에서 일어나는 모든 변화다. 단계 수는 1 + K.
4. `data-steps`는 이 슬라이드에서 단계 수에 들어가지 않는다. 선언형 요소가 있고 stepper가 없는데 `data-steps`가 있으면 콘솔 경고 한 줄과 lint 경고다(결정 12). stepper가 등록된 슬라이드는 압축하지 않는다(3.1절).

예: 요소 번호가 1(없음), 3, 3, 7, 퇴장 5이면 U = [3, 5, 7], 클릭은 3번이고 단계 수는 4다. 번호 3, 5, 7은 단계 2, 3, 4에서 일어난다.

**불변식(안정성의 핵심).** 단계 k ≥ 2마다 단계 k−1과 비교해 보임이 바뀌는 요소가 적어도 하나 있다. 빈 클릭은 없다.

**영향.**

| 대상 | 동작 |
|---|---|
| 번호가 2부터 빠짐없는 덱 | U = [2, …, K]이고 단계 수가 이전과 같다. 요소마다 같은 시각에 같은 상태: 바이트와 동작이 이전과 같다(합격 기준 5.2.7) |
| 번호가 건너뛰는 덱 | 빈 클릭이 사라진다. 이것이 의도한 변화다. 저장소의 덱(워크숍 2~4, 안내 덱 2~4, 템플릿 2~3)은 모두 촘촘해서 영향이 없다(2026-10-17 확인; lint가 빈 번호를 이미 경고했다). 영향 받는 덱은 클릭 수가 줄고 `info.steps`와 동기화 step 값이 바뀐다 |
| `data-steps`만 크게 쓴 덱(stepper 없음) | 남는 빈 클릭이 사라진다(감사 S29, S32). 의도한 변화이며 결정 12에서 정한다 |
| 인쇄, PDF | 마지막 클릭의 상태(변화 없음) |
| 전체 보기 썸네일 | 클릭 1(단계 1)의 상태(변화 없음) |
| 발표자와 청중과 리모컨 | `(slide, step)`의 step이 클릭 순위. 같은 덱이면 모든 창이 같은 엔진이라 일치한다. 번들된 옛 엔진 창과 새 엔진 창을 섞고 번호가 건너뛰는 덱일 때만 어긋난다(드문 경우, 프로토콜 `v`는 올리지 않는다) |
| 편집기 | Click k는 같은 순위. 편집기가 쓰는 번호는 빈칸을 허용하므로 클릭 사이에 끼울 때 다른 요소를 다시 쓰지 않아도 된다(중간 정수가 있으면). 정리(압축 저장)는 편집기의 선택이지 필수가 아니다 |
| 스크린 리더 | 3.6절 |

구현 메모: 엔진은 클릭마다 바뀌는 요소 목록을 미리 만들어 둘 수 있다(이동 한 번이 전체 요소를 훑지 않는다, 선택 최적화). 정렬은 시작 때 한 번이다.

### 3.8 값 검증 (v2)

런타임과 lint와 편집기 모델이 같은 파싱을 쓴다: 값을 앞뒤 공백을 지운 뒤 `/^[0-9]+$/`에 맞으면 정수로 읽는다(`4e0`, `0x4`, `2.5`, 빈 문자열, 음수, 글자는 모두 유효하지 않다. 지금 엔진은 `Number()`로 읽어 `4e0`을 4로 받던 것을 좁힌다).

| 속성 / 값 | 런타임 | lint | 편집기 |
|---|---|---|---|
| `data-step` 없음 | 처음부터 보임 | - | - |
| `data-step="1"` | 없는 것과 같다(조용히) | 오류(현재 규칙 유지: 의미 없는 값) | 줄 없음 |
| `data-step` 0, 음수, 소수, 글자 | 무시하고 처음부터 보임 + 콘솔 경고 | 오류 | 경고 줄(check this)로 표시, 첫 쓰기에서 정리 |
| `data-step-out` 비정수, 2 미만 | 퇴장 무시 + 콘솔 경고 | 오류 | 경고 줄 |
| `data-step-out` ≤ 등장(`data-step` 또는 1) | 퇴장 무시(끝까지 보임) + 콘솔 경고 | **오류로 올린다**(지금은 경고, 결정 17) | 경고 줄 |
| `--sk-step-ms`, `--sk-out-ms` = 0 | 전환 없이 상태만 바뀜(정상 값) | - | Duration 0 |
| 시간이 음수 | `clamp`가 0으로 올림 | 오류 | 입력 거절 |
| 시간이 숫자가 아님(NaN, 단위 없음) | CSS 선언이 무효라 전환 없음 | 오류 | 입력 거절 |
| 시간 또는 지연 > 10000ms | 엔진 CSS가 `clamp(0ms, 값, 10000ms)`로 한도에 맞춘다(`will-change` 해제 타이머도 같은 한도) | 오류 | 입력 한도 10s, 정수 ms, 50ms 스냅 |
| `--sk-step-delay`, `--sk-out-delay` 음수 | `clamp`가 0으로 올림(클릭 앞에서 시작하지 않는다) | 오류 | 입력 거절 |
| 시간과 지연의 단위 | `ms`와 `s`를 읽는다(지금은 `parseFloat`가 단위를 무시해 `.4s`를 0.4ms로 읽던 곳을 고친다) | 단위 없음은 오류 | - |

### 3.9 타임라인이 읽는 모델 (v2)

편집기 타임라인은 한 클릭 안의 시간 축 0~T 위에 항목마다 막대를 그린다. 필요한 값은 숫자 속성에서 바로 나온다.

| 필드 | 값 |
|---|---|
| `kind` | `in`(`data-step`) 또는 `out`(`data-step-out`) |
| `click` | 3.7절 순위(1부터, 단계 = click + 1) |
| `start` | 해당 방향의 지연(`--sk-step-delay` 또는 `--sk-out-delay`), 클릭 시점부터 ms, 0 이상 |
| `len` | 해당 방향의 시간(`--sk-step-ms` 또는 `--sk-out-ms`), 0이면 점으로 그림 |
| `end` | `start + len` |
| `T`(클릭 길이) | 그 클릭 항목들의 `end` 최댓값 |

- 시간 변수가 클래스에만 있을 때 편집기는 computed style로 읽는다. 인라인 값이 없는 요소를 편집하면 값을 인라인으로 쓴다.
- 등장 취소와 퇴장 취소(뒤로)는 지연이 없으므로 타임라인은 앞으로 가는 방향만 그린다.
- 같은 클릭 안의 순서는 (지연, 문서 순서)로 유도한다. 따로 순서 키는 두지 않는다.
- 이 필드를 계산하는 순수 함수(번호 파싱, 압축, 항목 목록, 목록 순서 유도)는 lint, 편집기 모델, 시험이 함께 쓰는 한 모듈로 둔다(결정 19). 브라우저 엔진(`slidekit.js`)은 같은 규칙을 바닐라 JS로 독립 구현하고, 두 구현이 같은 입력에서 같은 클릭 순위를 내는지 시험으로 비교한다(5.3절).

### 3.10 전환 관측 가능성 (v2, 스크럽 계약)

타임라인 스크럽은 엔진의 전환을 그대로 쓴다. 엔진은 다음을 지킨다.

1. 단계 이동 한 번의 시각 변화는 바뀐 요소의 `data-shown` / `data-away`(값 포함) 토글이 일으키는 CSS transition이고, 그 밖의 구동 수단(JS 타이머, Web Animations API 호출, 프레임 루프)은 없다.
2. 전환 중 `el.getAnimations()`에 `CSSTransition`이 `opacity`, `transform`(blur 지정 시 `filter`) 각각으로 나타나고, `effect.getComputedTiming()`의 `delay`는 해당 방향의 지연(앞으로 갈 때만 0 초과), `duration`은 해당 방향의 시간(2.4절 표)이다. 같은 요소의 `visibility` 전환은 보이게 될 때 즉시, 숨겨질 때 시간 + 지연 뒤이다.
3. 슬라이드의 `data-step-run` 속성은 전환이 도는 동안만 있다: 값 없음 = 앞으로, `back` = 되감기. 전환이 끝나거나 슬라이드를 떠나거나 점프(`data-step-instant`)면 지운다. 편집기는 이 속성을 쓰지 않고 읽기만 한다.
4. 편집기가 전환을 pause하고 `currentTime`을 맞춰도 엔진의 정지 상태 정리(`settle`)가 상태를 깨지 않는다: 정리는 속성 제거뿐이고 전환 객체를 건드리지 않는다.

검증: engine-verify에 합성 덱으로 단계 한 번 이동 직후 `getAnimations()`를 읽어 위 2번(요소, 속성, delay, duration, 앞과 뒤)을 확인하는 검사를 둔다. 4가지 사건(2.4절 표)을 모두 본다.

## 4. 화면 (편집기)

패널은 화면 아래, 지금 노트 패널 자리에 탭으로 둔다: **Notes** / **Animation**. Figma의 하단 타임라인 감각으로, 슬라이드 하나의 단계 구조를 한눈에 본다.

### 4.1 Animation 탭 (애니메이션 목록, 2026-10 개정)

처음 설계한 단계 격자와 막대는 숫자를 직접 다루게 해서 폐기했다(사용자 결정). 지금은 Keynote와 PowerPoint의 **애니메이션 목록**이다. 데이터(`data-step`, `data-step-out`, `--sk-*` 변수)와 엔진은 그대로이고 편집 화면만 바뀌었다.

```
 Notes | Animation                              [▶ Play]  Click 2 of 3        [+ Add animation]
 Click 1  ⠿  Title        In   [Rise ▾] [On click ▾]       [0.36s ▾] Custom 🗑
          ⠿  Photo        In   [Fade ▾] [With previous ▾]  [0.4s ▾]  Custom 🗑
 Click 2  ⠿  Caption      In   [Rise ▾] [On click ▾]       [0.36s ▾] Custom 🗑
 Click 3  ⠿  Arrow        Out  [Rise ▾] [On click ▾]       [0.36s ▾]        🗑
```

- 한 줄 = 한 개의 등장(In) 또는 퇴장(Out). 줄은 실행 순서(위에서 아래)이고 단계 숫자는 화면에 없다. On click 줄이 새 클릭 단계를 열고 그 아래 With previous, After previous 줄이 같은 단계에 묶인다(왼쪽에 `Click n` 소제목, 묶인 줄은 들여쓰기).
- 요소 하나에 In 하나, Out 하나까지(v1). 둘 다 있는 요소의 Out 줄은 효과와 시간이 In과 같고(요소 하나의 값, 2.4절) 바꿀 수 없다. Out은 항상 자기 In보다 뒤의 줄이다.
- 저장은 숫자로: On click = 새 `data-step`, With previous = 앞 줄과 같은 단계와 같은 지연, After previous = 같은 단계, 지연 = 앞 줄의 지연 + 시간. 편집기가 줄 순서와 시작 방식에서 계산해 쓰고(`animation-model.ts`의 `edit`, `layout`), 읽을 때는 같은 파일에서 줄을 다시 만든다(`buildList`: 단계, 지연, 문서 순서로 정렬, 단계의 첫 줄은 On click, 지연이 앞 줄 이하면 With, 크면 After). 표현이 정확하지 않은 조합은 가장 가까운 줄로 보이되 건드리지 않으면 속성이 바이트 그대로다. 외부에서(Claude가) 속성을 바꾸면 줄이 따라온다. (v2) 시작 방식은 저장하지 않고 지연 숫자에서 유도하며(2.6절), 줄마다 In과 Out이 각자 효과와 시간과 지연을 갖는다(2.4절). 타임라인 UI가 읽는 필드는 3.9절이다.
- 순서 바꾸기: 손잡이를 끌거나 줄 포커스에서 Alt+위/아래. 줄 하나만 옮겨 가고 각 줄의 시작 방식은 따라간다. Out이 자기 In 앞에 오거나 같은 단계가 되는 이동은 거절된다. 한 번 조작 = 실행 취소 한 건이고 바뀐 요소만 다시 쓴다(빈 단계 번호가 있었다면 첫 편집에서 당겨 붙는다).
- 줄을 누르면 그 요소가 선택되고 캔버스가 그 줄의 단계까지 실행된 상태가 된다(재생 헤드, 기본은 끝). 위의 `Play`는 처음부터 끝까지 재생한다. 캔버스 모서리 배지는 클릭 순서(`1`, `out 2`)다.
- `Add animation`은 선택한 요소에 In(이미 있으면 Out)을 더한다: 선택한 요소의 줄 바로 아래, 줄이 없으면 맨 아래에 On click으로. 요소의 첫 줄이 없을 때는 인스펙터의 `+ In`이 같은 일을 한다.
- Custom(줄마다 접힘, 기본 접힘)에 벗어난 상태 5값(opacity, x, y, scale, blur)과 Delay 직접 입력이 있다. 이름 있는 효과(Fade, Rise, Scale, Blur, Slide)는 파일에 저장되지 않고 값을 채우는 선택일 뿐이다(원칙 1).

### 4.2 Inspector의 Animation 섹션

최소로 둔다: `+ In`, `+ Out` 단추, 이미 있으면 Effect, Start, Duration 세 칸(목록과 같은 컨트롤)과 삭제. 숫자 칸(Appears, Disappears), 막대, 재생 헤드 숫자는 없다. 한 요소만 편집한다.

### 4.3 캔버스 표시 규칙

- 지금의 `data-sk-show-steps`(모든 단계를 한꺼번에 보임) 대신 재생 헤드 단계의 상태를 그린다. 헤드 기본값은 마지막 단계다(편집 중 모든 요소가 보이던 지금 느낌에 가장 가깝다).
- 선택한 요소는 헤드 단계에서 벗어난 상태여도 옅게 윤곽을 보여 계속 잡을 수 있게 한다(고를 수 없는 요소가 생기지 않게).
- Layers는 단계에 가려진 요소를 흐리게 표시한다.
- 편집기 밖의 읽기용 화면(발표자 미리보기)은 엔진이 보고하는 단계를 따른다.

### 4.4 키보드와 접근성

- 목록은 이름 있는 `list`(`Animations`), 줄은 `listitem`(`<요소 이름>, In`)이고 포커스를 받는다. 줄 포커스에서 Alt+위/아래는 순서 이동, Delete는 줄 삭제, Enter는 요소 선택과 헤드 이동. 칸은 네이티브 `select`(`Effect of ...`, `Start of ...`, `Duration of ...`)라 키보드와 스크린 리더가 그대로 된다.
- 헤드 라벨 `Click k of N`은 `aria-live`로 알린다. 포커스 링은 줄 바깥쪽 2px, 색은 지금 필름스트립과 같은 토큰이다.

### 4.5 실행 취소

- 시작 방식 바꾸기, 순서 이동(끌기와 Alt+위/아래), 줄 추가와 삭제, 효과와 시간 선택, Custom 값 입력은 각각 실행 취소 한 건이다.

## 5. 합격 기준과 검증

애니메이션은 안정성과 최적화가 합격 기준이다. 아래를 만족하지 못하면 기능이 있어도 출시하지 않는다. 기준은 `engine/test/verify.cjs`(항목별 단언), `engine/test/anim-stress.cjs`(퍼즈, 느린 CPU, 누수, 호환)로 고정한다.

### 5.1 최적화

1. 기본 전환은 `opacity`와 `transform`만 쓴다(합성 전용). `filter`(blur)는 사용자가 지정할 때만 켜지고 lint가 한 슬라이드에 3개 이상이면 경고한다. `width`, `height`, `top`, `left`는 애니메이션하지 않는다.
2. `will-change`는 상시로 두지 않는다. 전환이 도는 동안에만 슬라이드의 `data-step-run` 속성으로 켜고(가장 긴 전환 + 150ms 뒤 또는 슬라이드를 떠날 때 지움) 정지 상태에서는 모든 요소가 `auto`다.
3. 단계 이동 한 번의 스크립트 비용: 바뀐 요소에만 속성을 한 묶음으로 쓰고 레이아웃을 읽지 않는다(강제 reflow는 즉시 이동 한 번뿐). 요소 50개가 한꺼번에 바뀌어도 이동 한 번의 스크립트 시간 중앙값이 5ms 이내다.
4. 벗어난 요소는 전환이 끝나면 `visibility:hidden`이라 렌더, 히트 테스트, 접근성 트리에서 빠진다.
5. 큰 덱(약 12000노드)에서 방향키 이동 한 번의 비용(keydown 처리와 강제 스타일, 레이아웃)이 중앙값 15ms, p90 50ms 이내다(기준 측정은 중앙값 4~6ms, p90 8~9ms. p90은 전체 게이트가 낮은 우선순위로 돌 때 14~34ms까지 흔들려 기준의 5배로 둔다). 긴 작업(50ms 초과)은 환경 잡음과 섞여 단언하지 않고 건수와 트레이스만 출력한다.

6. **(v2) 시작 때 한 번의 비용**: 압축(정렬)과 클릭별 목록 만들기는 단계 요소 n개에 O(n log n)이고 단계 요소 1000개 슬라이드에서도 1ms 안팎이어야 한다(시작 비용 측정을 anim-perf에 더한다). 이동 한 번의 비용은 v1 기준(5.1.3, 5.1.5)에서 늘지 않는다. 퇴장 변수는 CSS 변수 폴백일 뿐 JS 비용이 없다.

### 5.2 안정성

1. 비활성 슬라이드(떠나는 중인 슬라이드 제외)의 자손은 어떤 순간에도 `visible`이 아니다(퇴장, 무작위 이동, 점프, 동기화, 크로스페이드 종료, 전환 도중 점프에서도).
2. 정지 상태 불변식: 전환이 모두 끝난 뒤 활성 슬라이드에서 요소가 보이는 것은 정확히 `N ≤ 단계 < M`이고, `data-step-run`, `data-step-instant`, `data-leaving`, `will-change` 같은 임시 상태는 남지 않는다.
3. 무작위 이동 퍼즈(시드 고정): 방향키, 같은 방향 3연타, 해시 점프, 청중 창 동기화를 섞어 매번 불변식을 본다. CPU 1배, 4배, 8배에서 모두 통과해야 하고 실패하면 시드와 이동 열 전체와 위반한 불변식을 출력한다.
4. 누수: 이동 수백 번 뒤 DOM 노드 수와 이벤트 리스너 수가 처음과 같다.
5. 움직임 줄이기에서는 전환 없이 상태가 바로 정확하다.
6. 인쇄와 PDF는 마지막 단계, 전체 보기 썸네일은 1단계, 번들, `doctor --layout`, 편집기 캔버스의 기존 경로에 회귀가 없다.
7. 호환: 사용자 덱(`vibe-coding-workshop`)의 기존 `data-step` 동작이 이전 엔진과 단계마다 같다(읽기 전용 사본으로 단계별 `visibility`, `opacity`, `transform`, `filter`를 비교).

8. **(v2) 압축 불변식**: 모든 덱과 무작위 번호 배치에서 단계 k ≥ 2마다 k−1과 비교해 보임이 바뀌는 요소가 적어도 하나 있다(빈 클릭 없음). 단계 수 = 1 + 서로 다른 번호 수.
9. **(v2) 압축은 번호 이름만 바꾼다**: 번호가 건너뛰는 덱은 그것을 `2…K`로 다시 매긴 덱과 모든 단계에서 요소별 `visibility`, `opacity`, `transform`, `filter`, `data-shown`, `data-away`가 같다(메타모픽 시험).
10. **(v2) 퇴장 변수 폴백**: `--sk-out-*`가 없는 요소는 이전 엔진과 모든 순간 같다(5.2.7을 확장). 퇴장 변수를 준 요소는 퇴장 전환에서만 그 값과 시간을 쓰고(2.4절 표의 4가지 사건에서 `transition-duration`과 `transition-delay`가 표대로), 등장 전 상태에는 `--sk-away-*`를 쓴다. `data-away`의 값은 퇴장 뒤에만 `out`이다.
11. **(v2) 전환은 CSS transition으로만**: 단계 전환은 `opacity`와 `transform`(blur를 쓰면 `filter`)의 CSS transition으로만 구현한다. JS 타이머나 별도 상태로 대체하지 않는다. 전환 중에는 `getAnimations()`에서 해당 요소의 `CSSTransition`이 `transitionProperty`별로 보이고, 지연은 `transition-delay`로(앞으로 갈 때만) 걸린다. 편집기가 이 전환을 pause하고 `currentTime`을 맞춰 프레임을 정확히 보여 주는 근거다(3.10절). engine-verify에 검사 하나로 둔다.
12. **(v2) 잘못된 값**: 3.8절 표의 모든 행에서 런타임이 던지지 않고 표대로 동작한다(무시하는 값은 보임 구간에 영향 없음, 경고 한 번).

### 5.2a 검토한 대안(채택하지 않음)

**비활성 슬라이드에 `content-visibility: hidden`**(자손 규칙 `... > [data-slide]:not([data-active]):not([data-leaving]) *`의 `visibility: hidden !important`와 `transition: none !important`는 `@supports not` 안에만 두는 안). 기대는 하위 트리의 렌더링과 스타일 계산을 건너뛰어 대형 덱의 이동 비용이 줄고 겹침 버그 클래스가 구조적으로 막히는 것이었다. 2026-10-15 마이크로벤치(슬라이드 40장 x 300요소 약 12000노드, 방향키 이동 한 번의 keydown 처리와 강제 스타일, 레이아웃, 변형마다 60회, 2~3회 반복, mac-cloud 소프트웨어 렌더링)로 비교했다. 아래는 중앙값 / p90 / 최대(ms)다.

| 변형 | 중앙값 | p90 | 최대 |
|---|---|---|---|
| a 현재(자손 hidden 규칙) | 5.3~6.3 | 8.1~8.8 | 10.9~101.4 |
| b 규칙 없음 | 5.0~6.4 | 7.8~8.4 | 9.4~9.5 |
| c 애니메이션 이전 엔진(`c11afe0`) | 4.2~5.4 | 8.6~9.0 | 9.1~88.9 |
| d `content-visibility: hidden` | 5.9~6.3 | 10.8~12.2 | 13.1~14.6 |

결론: a, b, c의 중앙값과 p90은 반복 간 변동 안이라 현재 규칙과 애니메이션 변경은 이동 비용을 늘리지 않는다. 최대치의 70~100ms 스파이크는 규칙이 없는 b와 이전 엔진 c에서도 나오는 환경 잡음이다. d는 중앙값이 같고 p90이 약 3ms 높아 이득이 없다(보이는 쪽 전환에서 렌더 재개 비용이 더해진다). 그에 더해 d는 computed `visibility`로 판정하던 불변식과 검사를 `checkVisibility` 기준으로 바꿔야 하고 미지원 브라우저 폴백 경로가 둘이 되어 복잡도만 늘어난다. 그래서 현재 규칙을 유지하고 이 제안은 채택하지 않는다. 회귀는 `engine/test/anim-stress.cjs`가 같은 방식의 큰 덱 이동 비용(중앙값 15ms, p90 50ms 이내)으로 잡는다. 긴 작업(50ms 초과)은 환경 잡음과 섞여 단언하지 않고 건수와 Chrome 트레이스 요약만 출력한다(`ANIM_REPEAT`, `ANIM_TRACE`).

### 5.3 항목별 검증

- **lint**: 3.2절의 규칙별 단위 테스트(퇴장이 등장보다 앞섬, 비정수, 빈 단계, 별칭 정보).
- **엔진 verify.cjs**: 합성 덱으로 (1) 등장만, 퇴장만, 등장과 퇴장, With previous, 지연; (2) 각 단계에서 `data-away`와 computed `visibility`, `opacity`가 맞는지; (3) 퇴장 전환 도중 슬라이드를 떠나는 점프에서 10, 100, 300ms에 비활성 슬라이드의 자손이 모두 hidden(`adac0cd` 계약); (4) 움직임 줄이기에서 전환 없음; (5) 뒤로 가기에서 퇴장한 요소가 돌아오고 등장한 요소가 사라짐; (6) 동기화와 해시 진입에서 같은 단계 상태; (7) 인쇄는 마지막 단계 상태, 썸네일은 단계 1; (8) 별칭 `data-step-effect`가 같은 결과.
- **편집기 e2e**: 시작 방식과 순서 이동(끌기, Alt+위/아래)이 `data-step`과 지연을 바꾸고 실행 취소 1건으로 되돌아감, 줄 누르기가 캔버스 상태를 바꿈, 선택 요소가 벗어난 상태에서도 잡힘, 키보드 조작, 별칭을 편집하면 변수로 변환, 파일 왕복(저장 후 다시 읽어도 같은 줄), 밖의 변경이 줄을 따라옴.
- **퍼즈 불변식**: 편집기 조작 퍼즈에 줄 이동, 요소 복제와 삭제, 슬라이드 복제를 섞어도 `data-step < data-step-out` 불변과 단계 수 계산이 유지되고 끝에서 실행 취소로 원본과 바이트 동일.
- **PDF와 썸네일**: engine-gradient 방식으로 PDF 쪽 수와 퇴장 요소의 부재를 확인, 전체 보기 썸네일 비교.
- **(v2) 압축 시험**(`engine/test/verify.cjs`, `anim-stress.cjs`): (1) 번호가 건너뛰는 합성 덱(1·3·7, 퇴장만, 퇴장이 다른 등장과 같은 번호, 큰 번호 9999)에서 단계 수, 클릭마다 보임, `info.steps`, 안내문 `단계 k / N`, 인쇄 마지막, 썸네일 첫 단계; (2) 메타모픽 퍼즈: 시드 고정으로 무작위 번호 배치를 만들고 `2…K`로 다시 매긴 쌍을 같은 무작위 이동으로 돌려 상태 열이 같은지(CPU 1배와 4배); (3) `data-steps`가 있는 선언형 슬라이드는 무시와 경고, stepper 슬라이드는 옛 규칙; (4) 청중 창 동기화에서 클릭 순위가 일치.
- **(v2) 호환 비교**: 저장소의 모든 덱과 템플릿에서 이전 엔진(v1 푸시본의 `slidekit.js`와 `slidekit.css` 사본)과 새 엔진을 단계마다 비교해 같다. 번호가 건너뛰는 합성 덱은 차이가 압축 규칙대로인 것만 허용한다(기대 표를 시험에 둔다).
- **(v2) 새 변수**: 퇴장 변수 폴백(없으면 등장과 같음), 퇴장만 다른 값을 준 요소의 4가지 사건별 전환 시간과 지연(`transitionrun` 이벤트나 computed `transition-duration`), 되감기에서 지연 없음, 연타와 되감기 퍼즈에서 `data-away` 값과 정지 상태 불변식. `s` 단위 시간을 읽는지(will-change 해제 타이밍).
- **(v2) lint**: 3.2절과 3.8절의 모든 행을 단위 테스트(`data-steps` 무시 경고, 빈 번호 경고 제거, 값 검증 표).
- **(v2) 공용 모듈 대 엔진**: 순수 모듈(번호 파싱, 압축)과 `slidekit.js`가 같은 입력(합성 + 무작위)에서 같은 클릭 순위를 내는지 비교한다.
- **부하**: `CPU_SLOW` 배율에서 단계 전환 도중 점프와 연속 입력으로 불안정이 없는지(`editor-perf`, 단계 100개짜리 합성 슬라이드의 패널 렌더 시간).
- **오프라인과 접근성**: 외부 요청 0건 유지(`engine-offline`), Animation 탭의 axe 점검과 키보드 e2e.

## 7. 결정이 필요한 것

각 항목은 번호, 질문, 추천과 이유 한 줄이다.

1. **퇴장에 다른 값을 허용할까?** v1 추천은 허용하지 않음이었으나 사용자 결정(A+)으로 v2에서 허용한다: `--sk-out-*`(2.4절). 없으면 등장 값을 따른다.
2. **벗어난 상태에서 부분 투명도(흐리게 남기기)를 허용할까?** 추천: v1은 항상 숨김(전환이 끝나면 `visibility: hidden`). 이유: "남아 있지만 흐린" 요소는 강조 기능(v2)과 겹치고 접근성 트리에 남는다.
3. **PDF의 단계 처리는?** 추천: 마지막 단계 상태(퇴장한 요소는 빠짐), 단계마다 쪽을 나누는 옵션은 나중에. 이유: 쪽 수와 기존 유인물 형식을 그대로 두고 지금 규칙("모든 요소 보임")과 퇴장이 없는 덱에서 같다.
4. **`data-step-effect` 별칭은 언제 없앨까?** 추천: 엔진 별칭은 slidekit-guide와 템플릿을 새 변수로 바꾼 뒤에도 한동안 두고, lint 정보를 켠 시점부터 두 번의 큰 기능 추가가 지난 뒤 제거 결정. 이유: 남이 받은 덱이 갑자기 효과를 잃으면 안 된다.
5. **스크린 리더가 퇴장을 알릴까?** 추천: v1은 알리지 않는다. 이유: 사라진 글자를 읽는 것은 소음이고, 새 내용이 나올 때 읽는 지금 동작이 핵심이다.
6. **`data-steps`(슬라이드 속성)를 유지할까?** 추천: 유지한다. 이유: 요소가 없는 빈 단계를 만드는 유일한 방법이고 SKILL, 템플릿, 동기화 정보가 이미 쓴다.
7. **요소별 곡선(easing)을 v1에 넣을까?** 추천: 넣지 않는다(`--sk-ease` 전역). 이유: 패널이 커지고 Figma Slides도 길이와 이징을 노출하지 않는다.

## 8. 참고

설계의 조사 근거는 team-lead가 확인한 것이며 이 문서를 쓰면서 외부 요청은 하지 않았다. 아래 링크는 각 문서의 최상위 안내 페이지이고 세부 문서는 그 안에서 찾는다.

- reveal.js Fragments(`data-fragment-index`, 같은 번호는 함께 나타난다): https://revealjs.com/fragments/
- PowerPoint 애니메이션 창(번호 목록, 시작 방식 3가지, 고급 타임라인 막대, 요소 위 번호): https://support.microsoft.com/powerpoint
- Keynote Build Order(한 요소에 등장, 강조, 퇴장 여러 항목): https://support.apple.com/guide/keynote
- Figma Slides(요소당 애니메이션 하나, 길이와 이징 없음: 커뮤니티 글 기준이라 확인이 더 필요하다): https://help.figma.com

네 도구의 공통점은 단계 번호 하나로 순서를 정하고 같은 번호는 동시에 일어나게 한다는 점이고, 이 문서는 거기에 파일 형식을 속성과 변수 두 가지로만 두는 제약을 더했다.
